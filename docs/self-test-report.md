## 验收清单（需求文档第五节）

| # | 验收项 | 结论 | 证据 |
|---|--------|------|------|
| 1 | 模组列表正确显示中文名与描述 | 自动验证（Lua）+ 截图 | 主菜单状态下，列表用的 `Locale.Lookup(Name)` 与详情用的 `Modding.GetModText` 均返回"智能区域规划器"及中文描述。modinfo 内嵌 `<LocalizedText>`，未启用时也能显示。附加内容界面未能截到本模组那一行（列表需滚动，无法合成点击）。附加内容界面的截图见下 |
| 2 | 启动栏出现图标按钮，点击弹出面板 | 自动验证 + 截图；真实鼠标点击需你确认 | `test_panel`：按钮注入、弹窗队列开关、Esc 处理、LuaEvents 开关。截图见下。游戏窗口拒绝合成点击，按钮回调与测试走的是同一个 `Toggle` 函数 |
| 3 | 学院+圣地秒级出结果；互惠更优解必须给出 | 自动验证 | `test_solver`：两区域走穷举，结果与 DMT 暴力枚举的最优提升完全相等（全 1 权重与只看科学权重各一次）。耗时见"性能"一节 |
| 4 | 结果行显示坐标与明细；悬停逐项来源与 DMT 图钉一致 | 自动验证 + 截图 | `test_ui`：结果行含坐标，tooltip 等于方案中 DMT 的 tooltip。`test_pins`：打钉后 DMT 为每个钉保存的 tooltip 与方案逐字相同。悬停截图见下 |

首次失败全部是测试本身的问题，修好后重跑通过，模组代码未改：
- `test_city`“禁止砍伐时排除树林”：同一格既有树林又有奢侈资源时，禁止砍伐下排除原因记为地貌、允许砍伐下记为资源（资源排除）。断言改为两种原因都接受。
- `test_built`：日本首都 1 环没有合适的空格，夹具把学院建在了 2 环城市尚未拥有的格上，没建成。夹具改为先把该格划给城市。
- `test_rules`、`test_overlay`：断言写死了“学院每个相邻区域 +0.5”，日本、高卢的特性用 `ExcludedAdjacencies` 换掉了这条规则（本模组按规则正确地不计）。断言改为按玩家的特性判断；与真实 DMT 钉逐项比对的部分对所有文明都通过。
- 另发现 `test_city`“已有地图钉锁定格子”删钉后没有 `Network.BroadcastPlayerInfo()`，钉留在地图上，影响后面的测试。改为按坑 19 删除；现在每局测试结束后地图上没有遗留的钉。

本轮新增或加强的游戏内用例：`test_pins` 检查钉名是城市编号（首都为“1”）；`test_solver`“别处已打钉的政府广场计入帝国上限”；`test_city`“可见的奢侈、战略资源排除，加成资源保留”。日本、高卢局里 `test_overlay` 的 36 个假想摆放与真实 DMT 钉逐项一致，说明本模组自建的修正缓存（AGENTS 坑 25）在游戏里生效。

**引擎可建格复核**（`tests/bench/probe_engine.lua`，前置 `tests/fixtures/unlock_all.lua` 给玩家全部科技与市政、首都拥有 3 环）：逐区域逐格比较“本模组候选格 + DMT 可放”与游戏引擎的可建格（`CityManager.GetOperationTargets`）。

## 开发中发现并已处理的问题

| 问题 | 处理 |
|------|------|
| DMT 在未揭示格子上调用 `CanPlacePin` 会报错 | 扫描时排除未揭示格；overlay 把单项错误记为不可放置，不中断整次求解 |
| DMT 的地块特征缓存只按坐标做键，结果会受调用顺序影响 | overlay 每次改动层前后都清缓存（`UpdatePinYields(pid, {})`） |
| 新建地图钉后，之前取到的钉对象失效，调用其方法使游戏崩溃（SIGSEGV） | 只保存钉 ID，每次用 `GetMapPinID` 重新取（AGENTS 坑 21） |
| `GetMapPin(x, y)` 会在空格子上新建钉 | 查找改为遍历 `GetMapPins()`（AGENTS 坑 22） |
| luaparse 的 5.1 模式会误报合法的 `break;` | 改用 5.3 模式解析，再用规则禁掉 5.1 没有的语法 |
| 游戏内计时器只有秒级精度 | 性能改由测试运行器测墙钟时间 |
| `ICON_YIELD_*_1` 图标缩小后只剩小点 | 权重图标改用城邦使者加成图标，并着深色 |
