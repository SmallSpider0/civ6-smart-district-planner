## 性能与单价（游戏内实测，2026-10-20）

### 单价（`tests/bench/cost_dmt.lua`、`cost_search.lua` 与各档实测拟合）

| 操作 | 单价 |
|------|------|
| 一次 DMT 调用（`GetBonusYields` 或 `CanPlacePin`，含清缓存） | 约 0.042 毫秒（5 次运行 0.032–0.054） |
| 一次布局评估（记忆命中为主） | 约 0.01 毫秒 |
| 一个模型搜索节点 | 0.002–0.005 毫秒 |
| `SDP_Tiers` 工作单位（≈ 1 次 DMT 调用 + 周边开销） | 一次算完时约 0.05 毫秒（每秒约 2 万单位）；分帧时单城每秒 7400–9900 单位，多城约 15000 单位 |

分帧时每帧约 30 毫秒，其中计算约 12 毫秒，其余是游戏自己绘制。把目标帧长从 1/30 秒放宽到 1/20 秒，精细档 8 个区域只从 1.8 秒变成 1.76 秒，所以保持 1/30 秒。

| 场景 | 快速 | 标准（含快速档前置） | 精细（含标准档前置） | 联合规划提升（逐城依次规划） |

### 预计耗时的校准

原先按"预算用满"估计工作量，单价也按 0.07 毫秒推算，预计耗时比实际长 5–10 倍。现在按实测的典型工作量（`SDP_Tiers` 各档 `Work`）和单价估计：

| 场景 | 原预计 | 现预计（本局第一次求解，默认速度） | 实际 |
|---|---|---|---|
| 单城标准档 6 个区域（同步） | 约 2.9 s | 约 0.2 s（显示"不到 1 秒"） | 0.25 s |
| 单城精细档 6 个区域（分帧） | 约 11 s | 约 0.9 s | 1.5 s |
| 单城精细档 8 个区域（分帧） | 约 13 s | 约 1.5 s | 1.9 s |
| 多城标准档 3 城 × 6 区域（分帧） | 约 5 s | 约 6 s | 4.4 s |
| 多城精细档 3 城 × 6 区域（分帧） | 约 19 s | 约 14 s（求解过一次后约 10 s） | 9.1 s |

每次算完的任务都会更新本机速度，之后的预计更准。

第一轮（MVP）的数据：3 个区域 0.06–0.11 s，4 个区域 0.08–0.19 s，8 个区域 0.18–0.80 s。

## 开发中发现并已处理的问题

| 问题 | 处理 |
|------|------|
| DMT 在未揭示格子上调用 `CanPlacePin` 会报错 | 扫描时排除未揭示格；overlay 把单项错误记为不可放置，不中断整次求解 |
| DMT 的地块特征缓存只按坐标做键，结果会受调用顺序影响 | overlay 每次改动层前后都清缓存（`UpdatePinYields(pid, {})`） |
| 新建地图钉后，之前取到的钉对象失效，调用其方法使游戏崩溃（SIGSEGV） | 只保存钉 ID，每次用 `GetMapPinID` 重新取（AGENTS 坑 21） |
| `GetMapPin(x, y)` 会在空格子上新建钉 | 查找改为遍历 `GetMapPins()`（AGENTS 坑 22） |
| luaparse 的 5.1 模式会误报合法的 `break;` | 改用 5.3 模式解析，再用规则禁掉 5.1 没有的语法 |
| 游戏内计时器只有秒级精度 | 性能改由测试运行器测墙钟时间 |
| `ICON_YIELD_*_1` 图标缩小后只剩小点 | 权重图标改用城邦使者加成图标，并着深色 |
| 随机开局可能是海上开局（毛利），第 1 回合无法建城 | 测试对局固定领袖和种子 |
| （第二轮）已探索的地图上选城址返回"无城址"：粗评前 20 名都离首都超过接力距离，组合全部不连通 | 精评按粗评顺序取"能连回本方城市或已精评城址"的城址（`SDP_SiteSolver` `NextSite`），离线加回归测试 |
| （第二轮）关闭面板后分帧计算停住：上下文隐藏后 `SetUpdate` 不再被调用（设计风险 2 不成立） | 计算中关闭面板时只隐藏窗口、保持上下文显示，算完再隐藏（AGENTS 坑 23） |
| （第二轮）面板关闭期间算完的结果会把预览画到地图上 | 面板关闭时算完即清除预览，重新打开页签再显示 |
| （第二轮）方案行未选中时深色字压在深色按钮上看不清；选中的页签字也看不清 | 按游戏 `TradeOverview` 的做法，选中、未选中各用一套文字 |
| （第二轮）预计耗时偏长 5–10 倍 | 按游戏内实测重新标定工作单位和各档典型工作量（见上） |
| （第二轮）离线基准里多城快速档在个别地图上比标准、精细档还好 | 标准档先跑快速档的起点、精细档先跑标准档的起点（`Prelude`，预算单独计算），精细档的起点数从 6 减到 4。离线：标准档计入地块从 98.4% 提到 99.5%，精细档 100%，精细档耗时少约 15%。游戏内复测全部通过 |
| （第二轮）测试工具：自然奇观等弹窗占住游戏事件队列，UI 里的揭示状态停止更新 | `game.py popups --close` 改为调用弹窗自己的关闭函数（AGENTS 坑 24） |
| （第二轮）Steam 账号在别处运行游戏时启动链接停在"踢掉另一会话"确认框 | 记入 AGENTS 环境说明，由用户处理 |
