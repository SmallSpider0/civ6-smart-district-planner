# #227 规划区域时一起规划改良设施的钉

> 2026-11-04 起。方案由 DracoYus 在 #227 上定：第 1–6 问 2026-11-03 07:15，第 7–11 问 2026-11-04（“均遵循建议”）。本文是实现计划和实现记录；交接时先读这里。

## 已定的方案（摘自 Issue）

- 第 1 问：方案 A。规划给区域带来相邻加成的改良设施，算进方案的分数，和区域一起打钉、一起撤销。
- 第 2 问：全额。还没建的改良按建好算，不打折。
- 第 3 问：除了给区域加成的格，高产出的格（如丘陵上的矿山）也打改良钉。改良钉分两类：
  1. **给区域的**（下称第 1 类）：区域旁边能让它多拿相邻加成的改良。求解时比较“这格放区域”和“这格建改良”哪个总分高，区域会因此挪位置。不管城市耕不耕作这格都打。
  2. **给耕作的格的**（第 2 类）：方案定了以后，城市会耕作的那几格里还没有改良的，按地块分假设的那种改良打钉。方案的分数和区域位置不变。
  - 同一格两类都想要时第 1 类优先，地块分也按它算。结果里报的相邻加成按全部改良钉都在时算。
  - 按规则定下的：每格建哪种改良取地块折算多产出最多的那种（有自己改良的资源只建那种，特色改良不打）；打平时取整局下来产出更多的（丘陵上矿山优先于农场）；能不能建按规则表判断（本方领土或能扩张到的格，不是被淹的沿海低地、古迹、看不见的资源），还没拥有的格写“需先扩张或购买”；砍伐跟“允许砍伐”，关着时不打要砍的改良，开着时要砍的写“砍伐后”，方案靠它拿相邻加成的森林、雨林不打要砍它的改良；挨着保护区、地块分取了“不建改良”的格不打；魅力：规划的矿山、采石场也按建好算进社区和保护区；选改良时把旁边区域给的产出算上。
  - 不做：改良之间的相邻（农场挨农场）。
- 第 4 问：没研究出科技也规划。
- 第 5 问：区域给改良的产出算进方案，范围是补充调研的第 1、2 类（朝鲜书院旁的矿山和农场、玛雅天文台旁的农场、高棉水渠和圣地旁的农场；已经建好或玩家自己打了钉的改良（含特色改良）因区域多拿的产出），按 #91 保护区的做法算进“地块”部分。
- 第 6 问：特色改良和城邦改良的位置这次不做，记在 #263。
- 第 7–11 问（评论原文的建议，均采纳）：
  - 7. 哪些格算“高产出”、要打改良钉？建议：城市会耕作的那几格全打，就是地块分已经算了的那几格。
  - 8. 每座城最多打几个？建议不另设上限：等于人口（至少是勾选的特色区域要的人口），和地块分算的格数一样。
  - 9. 面板上的开关怎么设？建议两个：“为区域规划改良”默认开（会改变区域放哪）；“给耕作的格打改良钉”默认关（不改变方案，只多打钉，人口多时地图上钉多）。
  - 10. “地块”权重设成 0 时，第 2 类还打吗？建议不打：那时方案不考虑城市耕作哪几格。第 1 类照常。
  - 11. 第 2 类在结果列表里怎么显示？建议每座城一行，如“改良设施：矿山 2、农场 3、伐木场 1”，悬停列出每一格的坐标和建好后的产出；预览显示改良图标。第 1 类照方案 A，写在它服务的区域下面。

### 改良怎么进求解和计分

1. **规则**（`SDP_Improve.Rules`，按 GameInfo 和玩家特性读，不写死文明）：`Gives[区域] = { 改良, 产出, 数量, 每几格 }`；`Takes[改良] = { 区域或“任意区域”或奇观, 产出, 数量, 每几格或“挨着就给” }`；`FeatureMatters[区域] = { 地貌 }`。
2. **每个布局的第 1 类**（`Model:Assign`，纯 Lua，不调 DMT，确定）：
   - 目标区域：布局里放下的、`Gives` 或 `Takes` 涉及它的区域。
   - 候选格：目标区域的邻格，没被布局、固定的区域和钉、奇观要的营地占用；空格条件同 #51（已揭示，无区域、奇观、自然奇观、改良、钉，不是被淹的沿海低地，本方的或能扩张到的）。
   - 每格能建的改良：有自己改良的可见资源只认那些；有地貌时保留地貌能建的，或（允许砍伐、地貌可砍、地貌对旁边的区域没有相邻加成时）砍掉后按地形能建的（记“砍伐后”）。只看所有文明都能建的改良（`SDP_Land` 的规则）。
   - 线性分：给旁边区域的相邻加成（玩家权重 × 数量 / 每几格）+ 地块变化（这格在耕作的几格里时：改良后的值 + 区域给它的产出 − 地块分原来假设的值）。每格取线性分最高的那种（同分按类型名），线性分大于 0 的留下。
   - 精确分（按“每几格”取整，计入已建的和钉上的同种改良）：按格序号逐个试拿掉，总分不降就拿掉，直到不再变。所以风云变幻里单独一座矿山不放。
   - 不调 DMT：选格是模型；相邻加成本身由 DMT 在棋盘上算（改良是静默槽，DMT 看得见）。
3. **地块分**：第 1 类的格按“建这种改良的值 + 区域给它的产出”算；已建的改良挨着规划的区域时加上区域给它的产出（只在耕作的几格里算，同 #91）。都按地块的固定折算 × “地块”权重。
4. **最后的完整评估**：区域 + 营地 + 第 1 类改良一起放上图层，DMT 报的相邻加成含改良；与搜索里的值一致（`Mismatch` 检查）。
5. **第 2 类**（不进搜索）：`PlanFor` 里按最终布局（含第 1 类）取每座城耕作的格，没有改良、不是第 1 类的格，按地块分假设的改良打钉；不打：地块权重为 0、开关关着、挨着保护区取了不建改良的、改良会让旁边区域的相邻加成变化的（该改良对旁边区域有相邻加成，或要砍掉对旁边区域有相邻加成的地貌）。所以第 2 类不改变任何区域的相邻加成，不进最后的评估。

### 打钉和撤销

- 第 1 类改良钉与区域同一批，名字是城市编号，撤销一起删；“替换之前的钉”时本模组的改良钉一起换掉，玩家自己的改良钉当作固定邻居（同 #51）。
- 第 2 类同一批打（开关开着时），名字同样是城市编号。

## 实现记录

2026-11-04，分支 `mac/improvement-tacks`。

### 做成什么样

- 计划里的模块和做法都照做了（见上）。比计划多出来、或和计划不一样的：
  - **求解器默认关**（`request.Improvements` 为 nil），面板传开关的值（默认开）。离线对比的旧变体因此不变；`_IMP` 变体打开改良规划，`_IMPW` 再加第 2 类（`tests/compare/cmp_sdp.lua`）。
  - **区域给改良的产出只在地块部分打开时算**：没有地块部分时，`Takes`（区域给改良的产出）不让区域成为目标，也不进 `Assign`（`SDP_Improve.New` 的 `Target`）。规则里一条都用不上时模型不交给搜索（`Model:Active()`）。
  - **`Assign` 按组算、按周边记住结果**：相距 2 格以上的区域没有共用的候选格和候选格的邻格，各组的改良互不影响；每组的结果只取决于组内区域 2 格内放了什么，按这个记住（`Model:Assign` → `AssignGroup`，`Ring2`）。离线测试逐个布局对比“共用一个模型”和“每次新建模型”，结果相同。没有这一步时高卢场景（每种区域都吃矿山）快速档慢 4 倍以上；现在约 2 倍（见下“离线对比”）。
  - **结果里改良的产出是整格建好后的产出**（地形、资源、地貌（砍伐的减掉）、改良本身含已有科技的加成、旁边区域给的），第 11 问“悬停列出每一格的坐标和建好后的产出”。
  - **魅力**：规划的改良按建好算进社区、保护区（`SDP_Appeal:Score` 的第三个参数）：改良自己的魅力（矿山、采石场 −1）和砍掉的地貌；改良格不再算保护区周边的“未开发”格。`Assign` 选改良时不看魅力（模型），搜索的精确评估看。
- 假世界（`tests/offline/world.lua`）：`spec.improveAdjacency` 加采石场（石头）、工业区“每两个相邻矿山 +1”“每个相邻采石场 +1”、农场“每个相邻学院 +1 食物”，特性 `TRAIT_TEST_IMPROVE`（学院每个相邻农场 +1 科技，`EFFECT_IMPROVEMENT_ADJACENCY`；农场挨着圣地 +2 食物，`EFFECT_ADJUST_PLOT_YIELD` 带两条地块要求）、`TRAIT_TEST_OTHER`（没有玩家有）。假 DMT 认 `AdjacentImprovement` 行和特性的改良相邻修正；改良钉不能保留的地貌、资源不算（与 DMT `GetRealizedPlotFeatures` 一样）。
- 裁判（`tests/compare/cmp_lib.lua`）：改良放置项带 `clear` 时可移除的地貌不算（“砍伐后”）。

### Codex 审查（PR #284，2026-11-04）

- **第 1 类改良也守资源自己的改良**（`SDP_Improve.lua` `Model:Options`）：属实。第 2 类在 `b44c9d6` 修过（`SDP_Land.AssumedImprovement`），第 1 类的候选只排除了收获，石油这类自己的改良不在规则里的资源（油井 `Buildable` 为假）会按地形给出农场，玛雅天文台旁的石油可能被打农场。两处共用新的 `SDP_Land.OwnResource`。测试：`spec_improve` “district improvements: a resource takes only its own”（假世界的铁只能建 `IMPROVEMENT_TEST_WELL`，旧代码在铁上给出农场）。
