# #338 监听没看到新打的 `auto` 标签

## 出了什么事

2026-11-07 21:21（北京时间）维护者在 GitHub 上给 #336、#329 打了 `auto`，之后没人评论，监听一直没叫醒代理。`tools/watch_issues.py` 只把带 `auto` 的 Issue 上的新 Issue、新评论当作要报的事，打标签本身不算；维护者和代理共用一个账号，这个账号的动作只记作已看。docs/maintaining.md §2 说维护者或合作者打了 `auto` 的 Issue 由代理自动处理，所以按工具 bug 修。

## 怎么改的

- 每轮本来就读一次带 `auto` 的全部 Issue（`labelled()`），现在它返回 `{编号: Issue}`，带上标题和链接。
- 状态 `state.json` 多一项 `labels`：`{"编号": 处理过的那次打标签的事件 ID}`。这一轮有、状态里没有的，就是新打的：读一次它的事件（`label_event()`，和判断评论该不该报共用同一次读取），记下 ID 和是谁打的。
  - 共用账号或 `$SDP_WATCH_USERS` 里的账号打的：报出 `LABELLED #N auto by 账号: 标题 链接`，进 `reported.log`，监听退出。
  - 别人打的：记进 `others.log`。
- 标签被去掉时从 `labels` 删掉，再打就算新的一次。两次轮询（2 分钟）之间又去又打的看不到，可以接受。
- 没有 `labels` 这一项时（升级后第一次运行、`--reset` 后），把当时已有的标签都记作看过，不读事件、不报。所以升级后不会把 #336、#329 等一次报出来（它们已经有人在做）。
- 同一轮里新开、开时就带 `auto` 的 Issue 只报一次：报了 `NEW ISSUE` 的不再报 `LABELLED`；共用账号开的（`NEW ISSUE` 只记作已看）报 `LABELLED`。维护者和代理共用账号、分不出是谁开的，维护者在 GitHub 上新开并直接打 `auto` 和这次的漏报是同一种情况，漏报比多叫醒一次代价大；代理自己开的多叫醒一次，按 sdp-watch“已经有人在做的就不用再做什么”处理（主会话 2026-11-07 定）。
- API 调用：每轮只对新出现的标签多读一次事件，平时不多。

## 测试

`tests/tools/test_watch_issues.py` 的 `LabelAdded`：首次运行不报；共用账号、合作者打的各报一次，再轮询不重复；别人打的进 `others.log`；去掉再打算新的一次；带标签新开的 Issue 只报 `NEW ISSUE`；共用账号带标签开的只报一次 `LABELLED`。前 6 条在旧代码上失败，最后一条是后加的。

## 还没验证

没有连真 GitHub 跑过：合并后值守重挂监听，第一次运行会把现有标签记作看过；下次维护者打 `auto` 时才看得到真的那一行。
