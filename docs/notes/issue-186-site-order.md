# #186 选城址页的城址顺序

合作者的要求：多城规划时城址按得分降序，靠前的先建；要靠别的城址钉接上的城址，把它依赖的排在前面。

## 以前

`SDP_SiteSolver` 的 `SolutionSites` 把一套方案的城址按地块编号（先行后列）排，结果列表、地图预览的编号、“打城址钉”的钉名（`SDP_City.SiteNumbers`，接在现有城市之后依次编号）都按这个顺序。新资源（玩家还没有的奢侈、战略资源）算在地块编号最小的那个有它的城址上。

## 现在

`SolutionSites(session, ctx, entry)` 按建城先后排：

1. 能接上的城址：离本方城市或城址钉（`session.Anchors`）不超过最远距离 D，或离已经排上的城址不超过 D。和求解时的 `Session:Connected` 是同一条规则，所以方案里的城址总能一个个排完（第二轮“不管接不接得上”只是兜底）。
2. 在能接上的城址里选分最高的：分 = 城址本身的分 + 在已排城址之后它拿到的资源分（`Shares` 在 `CopyTaken` 的副本上试算）。同分取地块编号小的。
3. 选中后正式记入资源（新资源算在它上面），排进列表，它也成为接力点。

资源分按顺序拆分，总和与顺序无关（奢侈：新种类的宜居度只算一次，多余的份数按买家上限卖；战略：`Short` 只对已有的种类成立，新种类的“首个 + 其余”和顺序无关），所以各城址的分加起来仍是方案总分（减冲突）。挑出的城址、方案总分、几套方案的先后都不变。

因为每一步选的是“在前面几个之后还值多少”，资源只会被前面的拿走，后面城址的分只降不升：不受接力限制时，列表的分是不增的；只有一个城址要靠后来的城址接上时，它后面才可能出现分更高的。

单城页、多城页不变。多城页的城市格子里城址钉仍按地块编号排（参与者顺序决定全帝国限一个的区域给谁），编号来自钉名，所以现在可能显示为“城址 5、城址 4”；要不要按编号排、让限一个的区域先给先建的城址，在 Issue 下问了合作者。

## 测试

- `tests/offline/spec_site_order.lua`（经面板按钮：数量、距离箭头、求解、打城址钉）：
  - 随机地图 4 座新城：每个城址都能经前面的接上；之后同样接得上的城址分不比它高；各城址分之和 = 方案总分 + 冲突；至少一套方案不再是地块顺序；结果行的坐标和“城址 N”编号、打出的钉名都按这个顺序。
  - 北向的窄地带、最远距离 4：顶上（地块编号小、有葡萄酒、马、铁和河）的城址只能经半路的城址接上，分更高也排在后面。
  - 两条在旧代码上都失败（第一个城址接不上）。
- `tests/compare/cmp_sdp.lua` 记录城址时按地块编号排，存的对比结果不因顺序变化。
