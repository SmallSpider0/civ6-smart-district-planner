# #91 第 6 题：1 点住房值几分（调研，2026-10-26）

#91 第 6 题。合作者（DracoYus）定了方向：城市住房紧时住房更值钱，宽裕时更便宜。本文查游戏里住房和人口增长的规则，把它换算成和相邻加成同一单位的分（1 分 = 每回合 1 点产出，按权重折算后），给出三个候选公式和例子。没有改模组代码，没有开游戏。

## 1. 现在的算法

`SDP_Land.HousingValue`（`SDP_Land.lua:491`），单城、多城（`SDP_Appeal.lua:462`）和选城址的水源分（`SDP_Sites.lua:225`）共用：

```
住房项 = h × [ HV(H₀ + 方案的住房, T) − HV(H₀ + 不放时的住房, T) ]
HV(n, T) = n                        n ≤ T
         = T + 1 − 0.5^(n − T)      n > T
```

H₀ 是城市现在的住房，T = max(人口, 3k − 2)（建齐 k 个特色区域要的人口），h 是“住房”权重。到 T 为止每点 1 分，之后每点减半。

问题：

- **拐点放错了地方。** 游戏里住房要比人口多 2 才全速增长（下节），而 HV 在住房 = T 时就开始减半。人口 5、住房 6 的城市现在增长已经减半，却被当成“住房够了”：社区 +2 住房只算 0.38 分。
- **大城反而算得多。** 人口 16、住房 15 的城市，社区 +2 算 1.5 分、+4 算 1.9 分，比人口 5 的城市高；可大城长一个人口要的食物是小城的 3.5 倍（下节），同样的住房要很久才能变成人口。
- **1 点住房 = 1 分没有依据。** 1 点住房最终能多养 1 个人口，1 个人口多耕作 1 块地，按地块模型的估值是 3 分左右；但这个人口要等城市长出来才有。

## 2. 游戏规则（已查证）

### 2.1 住房与增长速度

`GlobalParameters`（`DebugGameplay.sqlite`；来源 `Base/Assets/Gameplay/Data/GlobalParameters.xml:88-92`）：

| 参数 | 值 |
|---|---|
| `CITY_HOUSING_LEFT_50PCT_GROWTH` | 1 |
| `CITY_HOUSING_LEFT_25PCT_GROWTH` | 0 |
| `CITY_HOUSING_LEFT_ZERO_GROWTH` | −4 |

“住房 − 人口”（游戏叫 housing left）对应的增长倍数（城市详情里的“住房倍增”，`CityGrowth:GetHousingGrowthModifier()`）：

| 住房 − 人口 | 增长 | 游戏提示 |
|---|---|---|
| ≥ 2 | 100% | “人口增长率正常。” |
| 1 | 50% | “人口增速减缓50%。” |
| 0 到 −4 | 25% | “人口增速减缓75%。” |
| ≤ −5 | 0 | “人口增长率停止。” |

- 提示文字的分档在 `Base/Assets/UI/Panels/CityPanelOverview.lua:539-552`（`HousingMultiplier` 为 0、≤ 0.25、≤ 0.5、其他）。
- 百科（`Civilopedia_Concepts_Text.xml`，`LOC_PEDIA_CONCEPTS_PAGE_CITIES_12_CHAPTER_CONTENT_PARA_2`）：比上限低 2 或更多全速；低 1 降到 50%；等于上限 25%；“能在超过住房上限的情况下发展到 5 个公民，随后完全停止”。社区资料（Fandom、CivFanatics 住房指南）同样写“超出 5 停止”。`ZERO_GROWTH = −4` 按“低于 −4 停止”读与之一致；按“≤ −4 停止”读则差一档。没在游戏里核对，对下面的例子没有影响（例子里的城市最多超出 1）。

### 2.2 一次增长要多少食物、食物怎么算

- 每个人口吃 2 食物（`CITY_FOOD_CONSUMPTION_PER_POPULATION` = 2）。
- 从人口 p 长到 p+1 要的食物（`CITY_GROWTH_THRESHOLD` 15、`CITY_GROWTH_MULTIPLIER` 8、`CITY_GROWTH_EXPONENT` 1.5）：

  ```
  门槛(p) = 15 + 8 × (p − 1) + (p − 1)^1.5
  ```

  | 人口 | 1 | 2 | 3 | 5 | 8 | 10 | 16 | 20 |
  |---|---|---|---|---|---|---|---|---|
  | 门槛 | 15 | 24 | 34 | 55 | 90 | 114 | 193 | 250 |

  公式按参数名和社区资料写，没在游戏里逐档核对；实现时用 `CityGrowth:GetGrowthThreshold()` 校准（游戏速度会不会放大门槛也由它带进来）。
- 每回合计入增长的食物（`CityPanelOverview.lua:669-672`，注释说与 `City_Growth.cpp` 一致）：

  ```
  剩余食物 × max(1 + 宜居度增长修正% + 其他增长修正, 0) × 住房倍增
  ```

  宜居度修正来自 `Happinesses.GrowthModifier`（高兴 +10%、欣喜若狂 +20%，懊恼 −15% 等）。剩余食物为负时不乘这些倍数。

### 2.3 一个人口带来什么

| 来源 | 数 | 出处 |
|---|---|---|
| 耕作一块地 | 这块地的产出 | — |
| 或者当专家 | 学院 2 科学、圣地 2 信仰、剧院广场 2 文化、商业中心 4 金币、工业区 2 生产力等 | `District_CitizenYieldChanges` |
| 每个人口本身 | 0.5 科学、0.3 文化 | `SCIENCE_PERCENTAGE_YIELD_PER_POP` 50、`CULTURE_PERCENTAGE_YIELD_PER_POP` 30 |
| 代价 | 2 食物；每 2 人口要 1 宜居度 | `CITY_FOOD_CONSUMPTION_PER_POPULATION`、`CITY_POP_PER_AMENITY` |

社区的住房：基础 4（`Districts.Housing`），按所在格魅力 −2 到 +2（`AppealHousingChanges`），即 2–6。姆班赞固定 5。

## 3. 换成分：1 个人口 × 它在规划期内存在了多久

住房自己不产出，它让城市能多长人口。所以：

```
住房的价值 = 1 个人口的价值 c × 规划期内平均多出的人口
```

**1 个人口的价值 c。** 多出的人口去耕作城市还没耕作的最好一块地。地块模型（`SDP_Land`）已经给每块地估了价（食物、生产力 1，科学、文化 5/6，信仰 1/2，金币 1/4），这块地的价值就是 c，和“地块”那一项同一把尺子。地块用完了就当专家（约 2 产出，按倍数 1–1.7 分）再加每人口 0.67 分（0.5 科学 + 0.3 文化，× 5/6），所以 c 至少按 2 算。#88 对选城址的建议（“1 点住房按第 P+1 好格的产出算”）也是这个尺子。例子里用 c = 3（一块 2 食物 1 生产力的地）。

- 地块模型的格价值把食物也算 1。人口吃的 2 食物没扣：住房卡住时，剩余食物本来就大部分浪费（只有 25% 计入增长），多一个人口吃掉的是这部分。
- 生成场景的玩家有全部科技，格价值偏高（修了矿的丘陵 7 分）；真实存档的中期城市，下一块好地一般 3–4 分（#91 例 2：第 17 好的格 3 分）。

**平均多出的人口。** 按 2.1、2.2 的规则，从城市现在的人口、存的食物、每回合计入增长的食物出发，逐回合模拟 N 回合，算两种住房下的平均人口之差。增长进度按比例算作零点几个人口（门槛走到一半算 0.5），这样多 1 点住房也有连续的差别，求解器能分出魅力高一档的社区格。

这样算自然满足合作者的方向：

- 住房离人口近（紧），增长被压到 50%、25%，补上住房马上恢复全速，值钱；
- 住房比人口多很多（宽裕），规划期内长不到上限，多的住房一分不值；
- 大城长一个人口要的食物多，同样的住房兑现得慢，值得少。

## 4. 玩家社区

**已查证的规则**（Fandom、CivFanatics 住房指南、KeenGamer、游民星空等，与 2.1 一致）：住房至少比人口多 2 才全速；低 1 减半；到上限降 75%；超出 5 停止。

**玩家共识**
- 住房要提前留 2 点余量；无淡水的城早期最缺住房，先造粮仓、水渠。
- 早中期普遍“缺住房”，后期住房不再是主要瓶颈，人口多了也没多少好地可种（CivFanatics “What would make you build Neighborhoods?” 2020：投票里只有 25% 认为社区“已经值得建”；多数人一局只建一两个，或每 4–5 座城建一个）。
- 人口的边际价值递减：CivFanatics “Do you use specialists?” 里，Sostratus 认为 8、9 人口“基本没用”，10 人口能多一个区域名额才值；Denkt 按每个人口 0.5 科学 + 0.3 文化另加耕作的地估。
- 住房卡住时社区换掉农场划算：农场的食物在 −75% 增长下大多浪费（CivFanatics 住房指南）。

**个别意见**
- Reddit r/CivVI “Neighborhood worth it?”：有人为了给商业中心、工业区、学院排专家而建，后期仍缺住房；有人只为“极好”的社区（激励、尤里卡）建；文化胜利时住房不缺的城不建。

没找到把 1 点住房折成多少产出的帖子；知乎、NGA 没搜到专门讨论。

## 5. 候选公式

### A（建议）按游戏规则模拟增长

```
住房项 = h × c × [ 平均人口(H₀ + 方案的住房) − 平均人口(H₀ + 不放时的住房) ]
平均人口(H) = 从现在起 N 回合里，住房为 H 时每回合人口（含增长进度的小数）的平均
```

- 规则只用 2.1、2.2 的游戏数据：`GlobalParameters` 的三个住房档、门槛参数；城市自己的人口、存的食物、剩余食物和增长修正（`CityGrowth:GetFood`、`GetFoodSurplus`、`GetHappinessGrowthModifier`、`GetOtherGrowthModifier`、`GetGrowthThreshold`）。
- N 建议 50 回合（标准速度；按游戏速度缩放）。区域通常 20–40 回合内建好，再往后城市的需要会变，规划会重做。
- c = 地块模型里这座城下一块没耕作的最好格的价值，不低于 2；地块权重为 0（不建地块模型）时用 2。
- 城市中心钉、城址（还没有城）：人口 1、存粮 0，剩余食物按市中心格加最好一块格的食物 − 2 估。选城址的水源分也换成同一个函数，单城、多城、选城址三处对住房的估值一致。
- 计算量：住房总数只取几个整数，按 (城, 住房) 记忆，一次模拟 50 步，可以忽略。没有随机数，确定性不受影响。

### B 不看食物的简化式

```
第 j 点新住房的分 = h × c × 档(x_j) × 规模
x_j = 加上这点后的 住房 − max(人口, T)
档(x) = 1（x ≤ 2），0.5^(x − 2)（x > 2）
规模 = min(1, 门槛(5) ÷ 门槛(人口))      （人口 5 及以下为 1，人口 16 为 0.28）
```

就是把现在的 HV 拐点从 T 挪到 max(人口, T) + 2（全速增长线），再按“长一个人口要多少食物”给大城打折。不用读食物，容易解释；但不知道城市能长多快：剩余食物很多的大城被低估，食物很少的小城被高估。

### C 保持现在的算法

HV 拐点在 T，c = 1。作为对照。

## 6. 例子

c = 3、h = 1。A 用 N = 50，存粮 0；人口 5 的城每回合计入增长的食物 +5，人口 16 的城 +10（后面列了 +5、+15）。T 不超过人口（人口 5 的城计划 2 个以内的特色区域）。

**每个例子社区带来 +2、+4 住房时的分：**

| 城市 | 社区住房 | A（建议） | B | C（现在） |
|---|---|---|---|---|
| 人口 5，住房 6（增长已减半） | +2 | **2.5** | 4.5 | 0.38 |
| | +4 | **3.0** | 5.6 | 0.47 |
| 人口 5，住房 12（宽裕） | +2 | **0** | 0.07 | 0.01 |
| | +4 | **0** | 0.09 | 0.01 |
| 人口 16，住房 15（已超出 1，增长 25%） | +2 | **0.9** | 1.7 | 1.5 |
| | +4 | **2.7** | 3.0 | 1.9 |

（A 列 = 3 × 平均多出的人口：0.82、1.01；0、0；0.30、0.90。B 列 = 3 × 1.5、1.875；0.023、0.029；0.57、1.0。C 列不乘 c。）

读法：

- A：住房紧的小城，社区 +2 就值 2.5 分（和一个学院常见的相邻加成相当）；+4 只多 0.5 分，因为 50 回合里这座城只长得到 7–8 人口。住房宽裕时社区不加分。后期大城 +2 只够从 25% 升到 50%，值 0.9；+4 恢复全速，值 2.7。
- B：方向和 A 一样，小城高估约一倍（不知道它 50 回合只长得了两三个人口）。
- C：小城几乎不算、大城反而算得多，与合作者的方向相反。

**A 对食物和 N 的敏感度**（平均多出的人口，再 × c）：

| 城市 | +2 / +4 | N = 30 | N = 50 | N = 100 |
|---|---|---|---|---|
| 人口 5，住房 6，+5 食物 | +2 | 0.58 | 0.82 | 1.06 |
| | +4 | 0.59 | 1.01 | 1.72 |
| 人口 16，住房 15，+10 食物 | +2 | 0.19 | 0.30 | 0.39 |
| | +4 | 0.56 | 0.90 | 1.36 |

| 人口 16，住房 15，N = 50 | +5 食物 | +10 食物 | +15 食物 |
|---|---|---|---|
| +2 | 0.16 | 0.30 | 0.36 |
| +4 | 0.47 | 0.90 | 1.16 |

每多 1 点住房的边际（人口 5、住房 6、+5 食物，N = 50）：0.50、0.32、0.16、0.03、0、0；即第 3 点以后几乎不值，社区格魅力从“普通的”（4 住房）提到“迷人的”（5 住房）不再加分。人口 16、住房 15、+10 食物：0、0.30、0.41、0.19、0.02、0。

**选城址的水源**（A 的同一函数，新城人口 1，住房 = 水源 + 粮仓 2，N = 50，平均多出的人口）：

| 每回合食物 | 淡水 7 对无水 4 | 沿海 5 对无水 4 |
|---|---|---|
| +2 | 0.23 | 0.20 |
| +3 | 0.49 | 0.31 |
| +4 | 0.75 | 0.39 |

× c = 3 是 0.7–2.3 分；现在的水源分（HV，P ≥ 7 时）是 3 分。新城 50 回合内只长得到 5–7 人口，看得更远时淡水更值（N = 100、+3 食物：1.08 人口）。选城址的 N 要不要更长，留给 #88 一起定。

## 7. 没算进去的

- 区域名额：人口到 3k − 2 才能多建一个特色区域。A 只按“多一个人口多耕作一块地”估，不算名额；名额已经由地块模型的 P 管（`SDP_Solver.lua:140`）。
- 宜居度：每 2 人口要 1 宜居度，人口多了可能降一档宜居度。
- 新人口耕作的地不足 2 食物时，剩余食物会变少。A 按剩余食物不变模拟。
- 区域占掉农场、牧场等少掉的住房（`SDP_Appeal.ImprovementHousing`）现在只显示不计分；定了 A 以后它可以用同一个函数折成分，另议。
- 水渠、港口建筑的住房：单城页现在只算有 `AppealHousingChanges` 的区域（社区），水渠给的住房不算；选城址算港口建筑。A 不改变这些范围。

## 附录：模拟代码与命令

数字由下面这段 Python 算出（`python3 -I`，没有放进仓库）：

```python
def thr(p): return 15 + 8*(p-1) + (p-1)**1.5
def mult(left):                       # housing - population -> growth multiplier
    if left >= 2: return 1.0
    if left == 1: return 0.5
    if left >= -4: return 0.25
    return 0.0
def avg_pop(p, H, s, N, f=0.0):       # s = food counted toward growth per turn
    tot = 0.0
    for _ in range(N):
        tot += p + f/thr(p)           # progress toward the next citizen counts
        f += s*mult(H-p)
        if f >= thr(p): f -= thr(p); p += 1
    return tot/N
def A(p, H, s, d, N=50): return avg_pop(p, H+d, s, N) - avg_pop(p, H, s, N)
def HV(n, T): return n if n <= T else T + 1 - 0.5**(n-T)
def B(p, H, d, T=0):
    K = max(p, T) + 2
    return min(1.0, thr(5)/thr(p)) * (HV(H+d, K) - HV(H, K))
def C(p, H, d, T): return HV(H+d, T) - HV(H, T)
# A(5,6,5,2)=0.82  A(5,6,5,4)=1.01  A(16,15,10,2)=0.30  A(16,15,10,4)=0.90
```

规则数据：`sqlite3 DebugGameplay.sqlite "select Name, Value from GlobalParameters where Name like 'CITY_%'"`；`select * from AppealHousingChanges`；`select * from District_CitizenYieldChanges`；`select * from Happinesses`。路径用 `python3 -I tools/paths.py` 找。
