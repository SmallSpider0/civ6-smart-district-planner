# #162 “从本方其他城换格”默认打开，同分不换格（2026-10-29）

当初为什么默认关闭、在当前版本上重测的数字和方案见 #162 的两条评论（数据、决定）。维护者定方案 A：

- 单城、多城页的“从本方其他城换格”默认打开；
- 同分时优先选不用换的格，不再出现换了格却没有好处的方案；
- 已有存档里记住了这个开关的保持原样，新开的局用新的默认值；
- 放进 v1.6.2。

## 做法

- 默认值：`SDP_Panel.lua`、`SDP_PageMulti.lua` 的 `SWAP` 开关 `Default = true`，`m_swap` 初值 `true`。预设（`SDP_Settings` 的 `keeper.Use`）把开关设回 `Default`，所以选预设会把它打开；`SDP_Settings.Changed` 按新默认值比，关掉算“已改”（预设下拉框显示“自定义”）。
- 设置摘要：只在关掉时写“不换格”（`LOC_SDP_FOLD_NO_SWAP`，en “no tile swaps”），打开时不写；原来打开时写的 `LOC_SDP_FOLD_SWAP` 删掉。
- 同分不换格：`SDP_Search:Untangle`。搜索本身不变（集束、局部搜索、扰动都照旧，`Better` 的次级键仍是格子序号），只在出方案时（`Search:Solutions`，多城 `Session:Distinct`）把每套方案整理一遍：放在换来的格上的区域依次试
  1. 挪到本城自己的任一空格；
  2. 和另一个已放的区域对调；
  3. 和挨着它的一个已放区域一起挪到另一对相邻格（它自己的那格不用换）。

  只接受总分不低于原方案、换格数更少的一步；同一区域的几步里取总分最高、再换格最少、再格子序号小的。重复到一轮没有可接受的一步。因为只在总分不降时才动，方案的总分不会比不整理时低；开关关着时没有换来的格，整理什么也不做，方案和 main 完全一样。
- 什么算换格：单城看候选格的 `Swap`（`SDP_City` 扫描时记的原属城市）；多城看格子归本方哪座城、和放它的参与者（区域按所属城市，奇观按第一个能用这格的城市，和 `Session:PlanFor` 写“需从某城换格”的规则一样）是不是同一座。
- 整理会移动评估用的棋盘，所以 `Session:Result`（单城、多城）在整理后再 `board:Clear()` 一次；`Stats.Mismatch` 改为和整理后的那套方案比。

## 旧存档

`SDP_Settings` 只把和默认值（或预设值）不同的设置写进存档。旧版本里开关默认关闭，所以：

- 玩家打开过的存档里写着 `SWAP=1`，读回来仍是打开（新版本里它等于默认值，下次保存时不再单独写）；
- 玩家没动过、保持关闭的存档里**没有** `SWAP` 这一项，读回来用新的默认值，也就是**打开**。存档里没有“玩家选了关”的记录，没法和“从没碰过”区分，所以没有做迁移。

也就是说，决定里“记住了这个开关的保持原样”只对打开过的存档成立；保持关闭的旧存档打开后会变成打开。CHANGELOG 和 PR 里都写了这一点。

## 离线对比里的变体

`tests/compare/cmp_sdp.lua` 的普通变体（`STANDARD`、`STANDARD_LAND` 等）仍然不开换格，`_SWAP` 变体才打开（请求的 `Swap` 由变体名决定，不跟面板默认值走）。所以开发集、各结果文件的数字仍是“不换格”的，换格的数字只在 `tests/compare/results/swap.jsonl`。这次不改。

## 数字

命令（第二台机器，6 个 worker）：

```
node tools/compare.mjs -s '^R[MS]' -j 6 --add sdp:STANDARD_SWAP,sdp:STANDARD_SWAP_LAND \
  --only sdp:STANDARD,sdp:STANDARD_LAND,sdp:STANDARD_SWAP,sdp:STANDARD_SWAP_LAND --out logs/remote/swap162c.jsonl
```

76 行，结果换进 `tests/compare/results/swap.jsonl`。对照是 main `2ba2b62` 上同一条命令（#162 数据评论里的那一次）。加成是裁判（只加载 DMT 的独立状态）算的，换格数是裁判的 `swapped`。

| 标准档，只算相邻（`STANDARD` → `STANDARD_SWAP`） | 单城 14 个（`RS`） | 多城 5 个（`RM`） |
|---|---|---|
| 相邻加成 | 平均 +12.7%（0 到 +56%），6 个有变化，和 main 一样 | 平均 +19.3%（+2% 到 +28%），和 main 一样 |
| 要手动换格的区域 | 19%（57 个里 11 个；main 15 个，26%） | 27%（63 个里 17 个；main 19 个，30%） |
| 计算时间（换格 / 不换格，总时间） | ×1.16（main ×1.10） | ×1.99（main ×1.95） |
| 违反游戏规则 | 0 | 0 |

计入占地（`STANDARD_LAND` → `STANDARD_SWAP_LAND`）：单城平均 +12.8%（−12% 到 +44%），换格 26 个（46%，和 main 一样）；多城平均 +17.5%（+3% 到 +26%），换格 17 个（27%；main 20 个，32%）。

- 只算相邻时换了格、相邻加成却没涨的单城场景：main 是 RS07、RS10、RS13、RS14，现在只剩 RS07。RS07 不是同分：换格的方案魅力那一项（本模组目标函数里的魅力分）是 1，不换格的是 0.23，按本模组的目标它更好，所以保留。RS13 要第三种走法（和挨着的区域一起挪）才不换，第一版只有前两种时它从 2 格降到 1 格。
- 所有场景、所有变体的裁判加成都不低于 main；开关关着的两个变体 38 行方案和 main 逐格相同。
- 整理的开销：换格变体的 DMT 调用数单城多 5%（计入占地 8%），多城多 3%。计算时间是第二台机器上和别的任务同时跑的，单城 ×1.10 → ×1.16 里多半是机器负载的波动，按 DMT 调用数算整理只占几个百分点。
- 面板提示用只算相邻的数字：单城 +13%、多城 +19%，单城约两成、多城约三成区域要换格，多城慢约一倍。

开发集（开关关着，看同分规则有没有让方案变差）：第二台机器上 `python3 -I tools/refresh_results.py --check -j 4`，268 行重跑，方案全部相同，加成没有变高或变低，没有新的违规。这一轮跑在第一个提交上（整理只有前两种走法）；第三种走法也只在有换来的格时才动，开关关着时什么都不做，所以结论不变。
