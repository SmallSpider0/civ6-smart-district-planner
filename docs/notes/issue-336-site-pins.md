## 2. 客观错误：带钉的格被算给了新城（已修）

(70,30) 的耕作格里排第一的是 (68,27) 的雨林咖啡（5.21），奢侈分 3.75 也来自它；可这一格属于帕侬蓝。原因在 `SDP_City` 的 `ExclusionReason`：先查“格上有钉”（`PIN`），再查归属。`PIN` 属于“还能耕作”的排除（`SDP_Land` 的 `WORKABLE_EXCLUSIONS`），所以别的城的格、他国的格、别的城址一环的格、接不到的格，只要插了钉（这张图上是“勿砍”提醒钉、区域钉），就被当作这座城能耕作的格。另外选城址的粗评（`SDP_Sites.Coarse`）直接用 `SDP_Land.Workable`，不像单城、多城的 `SDP_Land.ForScan` 那样去掉区域钉、奇观钉占的格，所以别的城计划的商业中心钉 (71,28)、水坝钉 (71,27) 所在的格也被当成新城能耕作的格。

修正：

- `ExclusionReason`：归属（他国、本方别的城、城址一环、接不到）在钉之前查。对单城、多城的扫描也一样：别的城带钉的格从 `PIN` 变成 `OTHER_CITY`，不再算进这座城的地块；换格（`Swap`）的格照旧先过归属检查、再查钉。
- `SDP_Sites.Coarse`：去掉区域钉、奇观钉占的格（新的 `SDP_Overlay.PinSubjects`，`FixedSubjects` 也改用它）。不直接调 `FixedSubjects`：#226 的测试要求密铺时只给精评的城址建固定邻居，粗评每个候选调一次它会超出。

## 3. 主观部分：红框的城址为什么分低（问合作者）

改后 (70,31) 对方案 1 的 (73,34)：

| 分项 | (70,31) | (73,34) |
|---|---|---|
| 耕作（最好 7 格每回合） | 7.1 | 17.2 |
| 砍树、收获（一次性产出折算） | 27.6 | 19.2 |
| 区域相邻 | 6.3 | 8.3 |
| 淡水（住房） | 0（无水，住房 2） | 10（河边，住房 5） |
| 奢侈 | 0 | 7.5（咖啡、丝绸） |
| 合计 | 40.9 | 62.2 |

- 三环 36 格里：(70,31) 本方已占 9、瑞典 4、山 3；(73,34) 本方 6、瑞典 3、山 8。差别主要不在“被占的格多”，而在剩下的格：(70,31) 一带是平地草原、平原、雨林、树林，每格 2 食物左右，玉米只加金币，最好的 7 格平均不到 1.1 分；(73,34) 有火山土上的咖啡、树林丝绸、火山土丘陵。
- 框里的长处是雨林、树林多（砍树分最高）、离首都近。
- 待定：要不要给“填补本方城市之间的空地”或“离首都近”加分。建议不加：这是密铺的用途；本存档密铺 3～6 座也不选 (70,31)，因为同样近的位置里它分最低。问在 Issue 下。
