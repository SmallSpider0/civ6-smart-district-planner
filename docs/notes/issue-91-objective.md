# #91 目标公式与权重：单城、选城址、多城（2026-10-26）

#91 要求把三个页签的计算公式、默认权重写清楚，用具体例子看每个因素对分数和方案的影响，交合作者审查。本文按 v1.5.0 之后 `main` 上的代码写，公式后面注了代码位置。选城址页的分数尺度由 #88 单独分析，这里只列各项。

“分”的单位：除另有说明，1 分 = 每回合 1 点产出（按权重折算后）。相邻加成、地块产出都是每回合的量，所以能直接相加。

## 1. 单城

### 1.1 公式

结果汇总行的“加权提升”就是求解器最大化的目标（`SDP_Solver.lua:294`，各项在 `SDP_Search.lua:468` 的 `Search:Evaluate` 里相加）：

```
加权提升 G = 相邻 A + 地块 L + 住房与魅力 H + 覆盖 C − 距离 D
```

方案先比放下的区域个数，放得多的总是胜出（几个必建区域抢同几格时），个数相同再比 G（`Search:Consider`）。

**相邻 A**（`SDP_Overlay.Evaluate`、`SDP_Overlay.Score`，`SDP_Overlay.lua:257`、`:302`）

```
A = Σ（新区域 + 固定对象）Σ 产出 y  w_y × 相邻加成_y   −   同一批固定对象在不放新区域时的同一个和
```

- 相邻加成 = DMT 的 `GetBonusYields`，就是游戏放置界面显示的数，不含政策卡翻倍（需求约束 4）。
- y 是科学、文化、信仰、金币、生产力五项（`SDP_Rules.YIELDS`），w_y 是权重行前五列。
- 固定对象：城市四环内本方已建区域（含市中心）和地图钉。新区域挨着它们时，它们的加成会变（如旁边已建的商业中心多了一个相邻区域），这部分算进 A。结果里“得分会变化的已有区域”列的就是这些。

**地块 L**（`SDP_Land.lua`）

```
L = λ × [ W(放下方案后) − W(什么都不放) ]
W = 这座城最好的 P 块可耕作格的价值之和
P = max(当前人口, 3k − 2)        k = 已建特色区域 + 必建特色区域 + 要从候选里挑的个数
格的价值 = Σ 产出 y  p_y × 修上最好的改良后的产出_y   （p_y 见下表，固定）
```

- λ 是权重行的“地块”列（`LAND`）。p_y 固定，不随产出权重变（#53）：食物、生产力 1，科学、文化 5/6，信仰 1/2，金币 1/4（`SDP_Land.PLOT_WEIGHTS`，`SDP_Land.lua:39`）。
- “最好的改良”按玩家已有的科技、市政算加成（`SDP_Land.Context`）。可砍的地貌、可收获的资源，留着和砍掉取价值高的一种；留着就放弃砍伐、收获的一次性产出，一次性产出 × (1 + 9 × 科技市政进度) ÷ 20 折成每回合（`HARVEST_TURNS`、`ONE_TIME_GROWTH`）。区域建在格上之前玩家会先砍、先收，所以建区域本身不损失一次性产出。
- 结果是：占一块城市本来会耕作的格，代价是它的价值减去第 P+1 好的格的价值；占一块本来不耕作的格，没有代价。P 不小于建齐这些特色区域所需的人口（`SDP_Solver.lua:140`），即 k 个特色区域按 3k−2 人口算。
- 哪些格归这座城：已属本城的格；无主格离本方别的城更近时归那座城（`SDP_Solver.lua:150`）。打开“换格”时，从别的城换来的格算在原来那座城的地块损失里。
- λ = 0 时不建地块模型，L = 0。

**住房与魅力 H**（结果汇总行里叫“住房与魅力”；`SDP_Appeal.lua`，只在方案里有、或城旁已有/已打钉社区、保护区时出现）

```
H = h × [ HV(H₀ + 这些区域的住房, T) − HV(H₀ + 不放新区域时它们的住房, T) ]   +   保护区周边地块的产出
HV(n, T) = n                        n ≤ T
         = T + 1 − 0.5^(n − T)      n > T        （SDP_Land.HousingValue，SDP_Land.lua:491）
```

- h 是“住房”列。H₀ 是城市现在的住房（游戏的数；新城址是水源住房加第一个时代的市中心建筑，即粮仓），T 是上面的 P。住房到 T 为止每点 1 分，之后每多一点减半。
- 社区、保护区的住房按所在格的魅力定（`AppealHousingChanges`），魅力随方案变：相邻区域的 `Districts.Appeal`，建区域清掉的地貌、改良设施。
- 保护区周边地块：保护区设为必建时，古树林、避难所按魅力给周围未开发格加的产出（`Adjacent_AppealYieldChanges`，两座建筑都当作已建），按固定倍数 p_y 折算。地块列 λ > 0 时这些产出加到地块模型里那几格的价值上，再乘 λ（只算城市会耕作的格）；λ = 0 时按 p_y 全额计。从候选里挑出的保护区只显示、不计分（`SDP_Appeal.lua:374` 的 `counted`）。

**覆盖 C**（`SDP_Coverage.lua`）

```
C = c × 方案新覆盖的（城市, 类别）个数
```

- c 是“覆盖”列，默认 0（不建模型，结果与没有这一项时逐字相同）。类别：每种基础区域一类（工业区、娱乐中心、水上乐园），每个奇观一类；范围取该区域建筑的 `RegionalRange` 最大值（工业区、娱乐中心 6，水上乐园 9）。被覆盖的对象是本方全部城市（包括正在规划的这座）和全部城址钉；已被已建、已打钉的同类区域覆盖的不算。

**距离 D**（`SDP_City.DistanceCosts`，`SDP_City.lua:544`）

```
D = d × Σ 每个区域 max(0, 到最近的本方市中心的格数 − 1)
```

- d 是“距离”列，默认 0。游戏里区域造价与距离无关，这一项只表达“尽量靠近城市”的偏好（悬停提示里写了）。

**不计分的**
- 提醒钉（方案靠哪些树林、雨林拿加成）：只打钉。
- 区域占掉农场、牧场等少的住房（`SDP_Appeal.ImprovementHousing`）：只在结果里显示。计入目标时开发集上相邻加成和裁判的城市产出都变低（multicity-design.md 22.6）。
- 港口与商业中心分城、互斥区域：挑选时的约束，不是分数。
- 自动区域（水渠类、堤坝）：城市需要时当作必建加入，计分只有它占格的地块损失和它作为“相邻区域”给别人的加成。
- 奇观（单城页选了奇观时按只有这一座城的多城求解）：奇观本身没有相邻产出，它的影响全在邻居（剧院广场每挨一个奇观的加成）和占掉的格。

### 1.2 权重和开关

单城页、多城页的权重行都是 9 列，范围 0–3，步长 0.5（`SDP_Panel.lua:29` `MAX_WEIGHT`、`:1285`，列定义 `:45`–`:64`；多城页 `SDP_PageMulti.lua:48`）：

| 列 | 默认 | 乘在什么上 | 0 的意思 |
|---|---|---|---|
| 科学、文化、信仰、金币、生产力 | 1 | 该产出的相邻加成（A） | 这种相邻加成不算 |
| 地块 λ | 1 | 整个地块部分 L（p_y 固定倍数之上再乘），也乘保护区周边地块的产出 | 不计地块（取代原来的“计入占地”开关） |
| 距离 d | 0 | 每个区域离最近市中心的格数 − 1 | 不计 |
| 住房 h | 1 | 社区、保护区的住房价值 | 住房不计（保护区周边地块的产出照算） |
| 覆盖 c | 0 | 新覆盖的（城市, 类别）个数 | 不计 |

预设（`SDP_Settings.lua:34`–`:43`，只改权重和开关，不改区域）：

| 预设 | 与均衡不同的 |
|---|---|
| 均衡（默认） | — |
| 科技 | 科学 1.5 |
| 文化 | 文化 3 |
| 宗教 | 信仰 3 |
| 金币信仰减半 | 金币 0.5、信仰 0.5 |

倍数的来历见 [issue-49-presets.md](issue-49-presets.md)。

影响分数的开关：允许砍伐（只有单城页有，默认开；关掉时带可移除地貌的格不放区域，地块按保留地貌估值）、换格（默认关）、替换本模组之前的钉（默认关，开时那些钉不算固定对象）。提醒钉、分城不影响分数。

### 1.3 例子

数字来自离线对比框架：真实规则库（风云变幻）、原样的 DMT 代码、模拟的引擎，标准档，和面板默认设置一样（地块 1、住房 1、距离 0、覆盖 0、自动水渠和堤坝）。每次只改一个设置，从默认出发。表里：

- “本设置的总分”及各项：按这个设置自己的权重算；
- “动了几个区域”：和默认方案比，换了格子的区域数；
- “按默认设置重算”：把这个设置选出的方案放回默认设置下打分，方案之间就能用同一把尺子比：总分低于默认的，就是这个设置让方案在默认目标下变差了多少。

注意：生成场景里的玩家有全部科技（`cmp_mapgen.lua` 的 `techs = "all"`），所以早期场景的改良也按后期的加成估值，例如修了矿的草原丘陵值 7 分。真实存档的场景见 1.4 节。

#### 例 4：社区和保护区，住房与魅力项最大（`S01-rome-temperate-mid` 加社区、保护区）

## 2. 选城址（概要，详见 #88）

页签自己的权重、预设，与单城、多城不共用（`SDP_Sites.lua:27`–`:40`，面板 `SDP_PageSites.lua`）。粗评分给全部候选城址，前 M 个再用单城的搜索精评区域（`SDP_Sites.Coarse`、`SDP_Sites.Fine`，`SDP_Sites.lua:237`、`:404`）：

```
城址分 = 区域分 + 耕作分 + 地貌分 + 水源分 + 奢侈分 + 战略分 + 魅力分 − 可用格不足扣分
```

| 项 | 怎么算 | 权重（均衡 / 成长优先 / 区域优先） |
|---|---|---|
| 区域分 | 计划区域在该城址周围最好摆法的加权相邻加成（DMT），用页签的五项产出权重；距离成本（d，默认 0）也在这里扣 | 科文信金产 1 / 1 / 2 |
| 耕作分 | 区域占格后，最好 P 格的价值之和（绝对值，不是差）；格的价值按 `PLOT_WEIGHTS` × 页签上同一产出的权重（`SDP_Sites.PlotWeights`）；P = 3k − 2 | 食物 1 / 2 / 1，其余产出同上 |
| 地貌分 | 三环内砍伐、收获的一次性产出，× 地貌权重 × 进度 ÷ 20 | 1 / 1 / 1 |
| 水源分 | 住房权重 × [HV(该城址住房, P) − HV(无水城址住房, P)]，住房 = 水源 5 / 3 / 2 + 粮仓 + 计划里港口的建筑 | 1 / 2 / 1 |
| 奢侈分 | 宜居权重 × (新种类的 `Happiness` + 重复份数 × 1) | 1 / 1 / 1 |
| 战略分 | 战略权重 × (各格数量 + 新种类数 × 2) | 1 / 1 / 0 |
| 魅力分 | 魅力权重 × 可建区域格的平均魅力 | 0 / 0 / 0 |
| 扣分 | 计划区域数多于可建格时，每缺一格 2 分 | 固定 |

组合 K 个城址时再修正：两城都够得着的格归损失大的那城，奢侈、战略的新种类只算一次，两城的区域抢同一格扣较小的那份（`SDP_SiteSolver.lua` 头部）。耕作分是绝对值（几十分），区域分是增量（十几分），两者的比例和各项常数的尺度由 #88 分析。

## 3. 多城

### 3.1 公式

与单城相同，只是把所有参与的城（现有城市和城址钉）放在一起（`SDP_Multi.lua:1222`）：

```
加权提升 G = Σ 所有参与城 [ 相邻 A + 地块 L_城 + 住房与魅力 H_城 ] + 覆盖 C − 距离 D
```

和单城不同的地方：

- **相邻**：所有参与城的新区域和固定对象一起算，跨城相邻（两城的区域挨着互给加成）由 DMT 自然计入。不参与的城只作固定邻居。
- **地块**：每座城一个地块模型（`SDP_Multi.lua:531`）。P = max(当前人口, 3k − 2)，城址钉没有人口，取 3k − 2（`:528`）。两座城都够得着的格：已属某座参与城的归它，否则归最近的城。
- **住房**：每座城分开算 HV；城址的 H₀ = 水源住房 + 粮仓（`SDP_Land.ScanHousing`）。
- **覆盖**：被覆盖的对象包括本方全部城市和参与的城址钉。
- **距离**：到最近的本方市中心或参与的城址钉。
- **奇观**：可选奇观本身不计分，影响全在邻居（剧院广场）和占格；需要相邻某区域的奇观只认同城的区域；放不下的、少放的区域列原因。
- **帝国限一个的区域**（市政广场）：给要它的城里排在最前的那座，其余城记“已达帝国上限”，候选名额加一。
- 多城页没有“允许砍伐”开关，始终允许（`SDP_PageMulti.lua:66`）。
- 权重列、默认值、预设和单城页一样，两页各记各的。

## 4. 尺度上看着不对的地方

按影响从大到小：

1. **后期地块项比相邻项大，总分变负。** 后期每个区域都占一块城市会耕作的格（P 不小于可耕作的好格数），代价是格的全部价值；修了矿的丘陵在后期值 7 分，比一个区域常见的相邻加成（2–5）还高。例 3 地块 −25 对相邻 +17，开发集后期平均 −9.6 对 +17.6，真实存档合计 −117 对 +199，开发集后期 5/24、真实存档 4/14 的总分是负数。其中大半是常数（区域总得占格），不改方案，但玩家在结果行看到“加权提升：−8”。
2. **保护区周边地块一项远大于其余。** 例 4 里 29 分，相邻全部才 9 分；保护区的位置几乎只由它决定（26 次求解有 24 次在同一格）。它按古树林、避难所都已建成算（避难所要市政“保护地球”），按这些格都会被耕作算。地块列 λ 同时乘地块代价和这项收益，所以 λ 调高时有保护区的方案总分反而上升（例 4：λ = 3 时 102 分）。
3. **相邻和地块对同一种产出的估值不同。** 相邻加成里 1 金币 = 1 分、1 信仰 = 1 分（产出权重默认全 1，#53 定的）；地块里 1 金币 = 1/4 分、1 信仰 = 1/2 分、科学文化 5/6 分。同样是每回合 2 金币，长在商业中心上算 2 分，长在格子上算 0.5 分。
4. **覆盖每座城 1 分，与实际效果不成比例。** 一座城被工厂覆盖得生产力 +3（风云变幻 `Building_YieldChanges`，电厂再 +3–4），娱乐中心的动物园、体育场 +1 宜居度，覆盖权重 1 都只给 1 分。而且正在规划的这座城自己也算一个被覆盖的对象，只要放了工业区、娱乐中心就加常数 c（例 2、例 3）；必建时它不改方案，从候选里挑时它让求解偏向挑这两种区域。
5. **距离成本的单位没有游戏依据。** 0.5、1 在例 1–3 里只平移总分，不改方案；多城里在同分的摆法里挑近的。3 才明显改方案，这些方案按默认设置重算，单城低 2–4 分，多城低 11.5 分。
6. **住房 1 点 = 1 分。** 到目标人口为止每点住房和每点相邻产出等价；之后减半。没有对照依据，社区的住房（最多 6）和一座城的相邻加成同一量级。
7. **有保护区时标准档不稳**（不是公式本身的问题，但和这一项的尺度有关）：例 4 用标准档，25 个设置里 12 个找到的方案比默认方案还差，最多差 6.25 分；精细档没有这种情况。别的例子标准档都没有。
8. （文字）“住房”列的悬停提示（`LOC_SDP_WEIGHT_HOUSING`）还写着保护区周边产出“按各产出的权重计（打开‘计入占地’时……）”，#53 之后已是固定倍数、没有这个开关了，要改。

没发现的问题：五项产出权重的作用和预期一致（0 时这种加成不算，3 时方案往这种产出偏）；预设的效果与 #49 的实验相符。

## 5. 需要你定的问题

每题第一个是建议。

1. **后期地块代价**：建议 C，目标不变，结果里把地块单列为代价，不显示负的“加权提升”（第三位版本号，工作量小）；A 保持；B 第 P+1 好的格不低于一个专家的产出（如 2 分），给每块格的代价封顶（方案会变，第二位版本号，要重跑离线对比）。
2. **保护区周边地块**：建议 B，只算古树林，避难所等学了“保护地球”再算；A 保持；C 打折。另外 λ 是否继续乘这项收益（建议不乘：地块列的意思是“代价”）。方案会变，第二位版本号。
3. **相邻产出的默认权重和地块倍数是否一致**：建议 A 保持（#53 定过，“金币信仰减半”预设给想要的人）；B 默认改成金币、信仰 0.5；C 地块也全 1。
4. **覆盖的分值**：建议 C，本城自己不算被覆盖的对象（必建的区域只是去掉常数；从候选里挑时，现在这个常数会让它偏向挑工业区、娱乐中心）；B 按建筑效果折算（工厂 3 分）；A 保持。
5. **距离成本**：建议 A 保持（默认 0，只是偏好）；B 换成有依据的分值（买地价、取得格子的先后）；C 去掉这一列。
6. **住房 1 点的分值**：建议 A 保持 1，没有更好的依据；B 换别的折算。
7. **汇总行**：建议 B 先写相邻加成，再写其他各项，与第 1 题一起做；A 保持。

## 9. 定下的改动与实测（2026-10-26，分支 mac/objective-fixes）

合作者在 #91 定的七项，按这些实现。“实测”都在第二台机器上跑，命令在本节末尾。

### 9.1 结果行（第 1、7 题）

计分不变。汇总行先写加权相邻加成，括号里再写打开的各项，顺序同权重行：地块、距离、住房、覆盖，如“加权相邻加成：+17（地块 -25；距离 -3.5）”。各项之和（求解比较用的 G）不再显示；汇总行的悬停提示说明方案按它排序、为什么不显示。方案按钮上的数字改成该方案的加权相邻加成，悬停先列各项再列挑出的区域。多城页悬停原来写“逐城依次规划时加权提升为 X”（也是个可能为负的和），改成“与逐城依次规划相比：+ΔG”。住房项的名字从“住房与魅力”改成“住房”（保护区周边产出已移走，见 9.2）。

### 9.2 保护区（第 2 题）

- 区域网格里默认“不建”，点一下变候选、再点必建（`SDP_UI.DefaultState`：有 `Adjacent_AppealYieldChanges` 行的特色区域）。选城址页的区域本来都不勾选，不变。
- 古树林、避难所给周边未开发地块的产出从住房项移到地块项（`Search:AppealParts`、`LandDelta`），估值同其他地块：这块地值“修上最好的改良”和“不修改良（地貌保留）加保护区产出”中高的一种（`SDP_Land.PlotValues` 第三个返回值、`ScoreTaken` 里 `max(Tile, Bare + extra)`），挤进城市最好的 P 块才计入，乘地块权重；地块权重为 0 时不计（结果行标“‘地块’权重为 0，不计分”）。原来按 `Tile + extra` 算，修了矿的丘陵挨着保护区会被当成“矿 + 保护区产出”，这在游戏里拿不到。
- 只算玩家现在能建的建筑（`SDP_Appeal.TileRows`）：建筑的 `PrereqTech`、`PrereqCivic` 玩家已有，或与区域本身的前置相同（随区域一起解锁）。风云变幻规则：保护区和古树林都要“神秘主义”，避难所要“保护地球”（`Buildings.PrereqCivic`，`DebugGameplay` 导出的规则库核对过），所以古树林总算，避难所学了“保护地球”才算。
- 从候选里挑出的保护区照旧只计住房、周边产出只显示。
- 选城址页给城址打分时本来就不建魅力模型（`SDP_Sites.Fine` 不传 `Appeal`），保护区的住房和周边产出都不计，这次不变。

例 4 重算（`S01-rome-temperate-mid` 加社区、保护区，精细档，距离 0；生成场景的玩家有全部市政，所以避难所也算）：

|---|---|---|---|---|---|
| 原来（第 1.3 节） | 44.08 | 9 | 0 | 35.08（其中保护区周边 29.08） | — |

### 9.3 距离默认 0.5（第 5 题）

`WEIGHT_COLUMNS` 的 `DISTANCE` 默认 0 → 0.5，单城、多城页共用；预设都不设距离，跟着默认走。设置存档只记与默认不同的值（`SDP_Settings.Encode`），所以从没改过距离的存档读出来是 0.5，改过的（包括特意设成 0 的）保持原值，不需要迁移。选城址页的距离成本是另一列，默认仍是 0。

开发集 84 个场景，地块开（面板默认），标准档，距离 0 对 0.5（`STANDARD_LAND` 对 `STANDARD_LAND_DIST050`）；“相邻”是裁判算的相邻加成，“地块”是本模组的地块项：

| 阶段 | 场景 | 方案变了 | 动了的区域 | 相邻 0 → 0.5 | 地块 0 → 0.5 | 距离扣分（0.5 时） |
|---|---|---|---|---|---|---|
| 早期 | 24 | 6 | 9 / 48 | 119 → 119 | 0 → 0 | −14 |
| 中期 | 24 | 13 | 41 / 100 | 289 → 287（−0.7%） | −12.8 → −13.8 | −24.5 |
| 后期 | 24 | 21 | 77 / 165 | 423 → 420（−0.7%） | −233.4 → −236.4 | −61 |
| 多城 | 12 | 12 | 99 / 171 | 413 → 410（−0.7%） | −56.5 → −64.2 | −59 |
| 合计 | 84 | 52 | 226 / 484（47%） | 1244 → 1236（−0.6%） | −302.7 → −314.4（多占 3.9%） | −158.5 |

相邻加成变低的场景 14 个、变高的 4 个（标准档是启发式，挑近的有时也碰到更好的）；没有新违规。裁判算的城市产出（`output`，计入占地）911 → 875。真实存档 14 座城（`RS01`–`RS14`）：4 座的方案变了，56 个区域动了 10 个，相邻合计 199 → 199（一座 −1、一座 +1），地块项 −117.25 → −118.25。耗时没有变化（开发集单城平均 4.7 秒对 4.8 秒，多城 49 秒对 47 秒，同一台机器）。

### 9.4 覆盖不算本城（第 4 题）

区域或奇观不再把它所属的那座城算作被覆盖（`SDP_Coverage` 的 `InReach`、`List`、`Reach` 多一个 owner；`SDP_Search` 的 `CoverOwner`：单城页是这座城，多城页是该槽位所属的参与城，奇观按它所在格属于哪座参与城）。别的城，包括别的参与规划的城，照算。覆盖结果文件全部重跑核对：`coverage_single`（42 行）、`coverage_sdp`（72 行）、`coverage_player`（84 行）方案都没变，因为这些场景的区域是必建的，本城那 1 分本来就对所有摆法一样；变化只在从候选里挑时出现。覆盖列悬停提示里的实测数字因此不用改。

### 9.5 住房的分（第 6 题，方案 B）

合作者选了 [issue-91-housing-value.md](issue-91-housing-value.md) 的方案 B，并把拐点定为“目标人口 + 1”（长到目标人口 T 的最后一步是 T − 1 → T，这时住房 T + 1 就满速）：

```
每点住房算 1，直到 K = max(T + HOUSING_TARGET_SPARE, 人口 + HOUSING_GROWTH_SPARE)，之后每点减半
整项乘 S(人口) = min(1, 门槛(5) ÷ 门槛(人口))，门槛(p) = 15 + 8(p − 1) + (p − 1)^1.5（GlobalParameters）
HOUSING_TARGET_SPARE = 1，HOUSING_GROWTH_SPARE = 2
```

城址钉、选城址页的新城按人口 1 算（`S = 1`）。没有乘“1 个人口值几分”（方案 B 例子里的 c = 3）：住房项的尺度仍由“住房”权重定，c 留到以后再议。游戏里 `CityGrowth:GetGrowthThreshold()` 只给城市当前人口的门槛，`S` 用规则表的公式算两头，游戏速度对两头一样，比值不受影响；游戏内测试 `test_land.lua` 核对公式和首都的 `GetGrowthThreshold()` 一致。

例子（方案 B 的例子，c = 1）：人口 5、住房 6、目标 7 的城，+2 住房 2 分（原来 1.5）；人口 5、住房 6、目标不超过 5 的城，+2 住房 1.5 分（原来 0.38）；人口 16、住房 15、目标 16 的城，+2 住房 0.57 分（原来 1.5）。

实测：开发集（`full_rejudged`，268 行）方案都没变；`land.jsonl`（84 行）、`real.jsonl`（81 行）里变了的行，除 `RM04` 外在 `main` 上重跑也一样（这两个文件存的结果比 `main` 旧，不是这次改动造成的）；`RM04-continents-netherlands-4c` 的标准、快速、精细档变了：住房项 2 → 0.20（后期大城打折），裁判算的相邻加成 37 → 38。选城址（`sites_v150`，24 行）方案都没变。例 4 的住房项 6 → 1.71（16 人口的城，S = 0.285），住房权重 3 时社区不再为多 1 点住房换格。
