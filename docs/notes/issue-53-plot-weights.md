# #53 地块产出按固定倍数计（2026-10-25）

调研、实验方案、参照布局和三次决定都在 #53 的评论里。这里记 v1.5.0 怎么实现、哪些地方跟着变、测试和数字的出处。

## 决定

- 区域产出的权重（权重行）默认仍是全 1，只管区域的相邻加成（以及社区、保护区的住房、覆盖、距离这些列）。
- 地块产出与它相互独立，按固定倍数计，照另一个模组“加权综合收益权重”的设置（食物 12、生产力 12、金币 3、科技 10、文化 10、信仰 6），按食物、生产力 = 1 换算：

  | 产出 | 倍数 |
  |---|---|
  | 食物、生产力 | 1 |
  | 科技、文化 | 5/6 |
  | 信仰 | 1/2 |
  | 金币 | 1/4 |

  金币、信仰与购买价一致（1 生产力 = 4 金币 = 2 信仰，`GOLD_PURCHASE_MULTIPLIER`、`GOLD_EQUIVALENT_OTHER_YIELDS`）。
- 砍伐、收获的一次性产出也按这组倍数计（一次性产出本身的系数 `FEATURE` = 1）。
- 权重行去掉只用于地块的“食物”“收获”两列。
- 补充决定（同日）：玩家可以设一个整体的“地块”权重，放在去掉的两列的位置，乘在整个地块损失上，默认 1（地块系数 λ 默认仍是 1），0 表示不计；“计入占地”开关和它重复，去掉。
- 补充决定（同日）：所有权重的步长改为 0.5，范围仍是 0–3。

## 代码

| 位置 | 改动 |
|---|---|
| `SDP_Land.PLOT_WEIGHTS` | 上表，加 `FEATURE = 1` |
| `SDP_Land.Scale`、`SDP_Land.PlotWeights` | 请求权重里的 `LAND`（缺省 1）；`PLOT_WEIGHTS` 的六种产出乘以它（一次性产出由产出权重算出，跟着一起乘，`FEATURE` 不再乘） |
| `SDP_Solver`（本城和换格来源城的地块模型）、`SDP_Multi`（每座城的地块模型） | `SDP_Land.ForScan` 传 `PlotWeights(Scale(request.Weights))`，不再传请求的产出权重 |
| `SDP_Appeal` | 保护区给周围格的产出（`TileWeights`）按 `PLOT_WEIGHTS` 计：这些产出落在被耕作的格上，属于地块。计入地块时再乘 `LAND`（它们抬高的是地块模型里的格）；地块权重为 0（不计地块）时照原样全额计 |
| `SDP_Panel.lua` 的 `WEIGHT_COLUMNS` | 去掉 `YIELD_FOOD`、`FEATURE` 两列，在产能后面加 `LAND`；单城、多城页 9 列，列宽 50。去掉“计入占地”开关（`LandCheck`、`MultiLandCheck`），请求的 `Land` = `LAND` > 0。`SetLand` 只留给测试：开 = 1（已设过就不动），关 = 0 |
| `SDP_UI.BuildWeights` | 每列的步长默认 0.5（原来 1，距离列原来就是 0.5） |
| `LOC_SDP_LAND` | 原来是开关的提示，现在是“地块”列的提示，写明各项产出的固定倍数 |

存档里 #57 记下的 `LAND=0`（原来的开关关掉）读回来就是地块权重 0，意思不变。

`SDP_Land.Weights`、`SDP_Land.Context` 的参数不变：它们按传进来的权重给格子估值，缺的按 1。区域规划传 `PLOT_WEIGHTS`。

## 选城址页

最初没改（城址页的权重衡量“想要什么样的城址”，“成长优先”靠食物权重），作为待定项挂出。维护者 2026-10-25 定：选城址页的地块也按固定倍数计，重测排序。

做法（最简单、可解释）：城址的地块产出按 `SDP_Land.PLOT_WEIGHTS` 乘页签上同一产出的权重（`SDP_Sites.PlotWeights`）。页签权重默认全 1，就是固定倍数；“成长优先”把食物设为 2，食物格的价值仍是 2 倍。收获列照旧乘一次性产出。页签上的产出权重同时照旧用于区域潜力的相邻加成，这一点不变。

排序变了多少、“成长优先”还起不起作用：见下文“选城址排序的复测”。

## 选城址排序的复测

开发集的 12 个选城址场景（`C01`–`C12`），均衡（`sdp:STANDARD`）和成长优先（`sdp:STANDARD_GROWTH`，`cmp_sdp.lua` 里加的变体：食物 2，其余同均衡）各跑一次。改前用 main（816ef74）加同一个变体，改后用本分支：

```
node tools/compare.mjs -s '^C\d\d' -p sdp --only sdp:STANDARD,sdp:STANDARD_GROWTH --add sdp:STANDARD_GROWTH -j 2 --out OUT.jsonl
```

结果 `tests/compare/results/sites_v150_before.jsonl`（改前）、`sites_v150.jsonl`（改后）。

| | 均衡 | 成长优先 |
|---|---|---|
| 城址组合不变的场景 | 8 / 12 | 6 / 12 |
| 第一个城址不变 | 8 / 12 | 7 / 12 |
| 裁判的区域潜力合计 | 146 → 147 | 138 → 146 |
| 裁判的地块值合计 | 712 → 695（−2.4%） | 710 → 685（−3.5%） |
| 淡水城址 | 3 → 3 | 5 → 4 |
| 新奢侈品种类 | 8 → 7 | 8 → 5 |
| 违规 | 0 | 0 |

- 裁判的“地块值”是每个城址最好的 8 格各项产出不加权相加，金币、信仰和食物一样算 1，正是改前的算法，所以改后在它上面低一点是预料之中的：改后宁可要食物、生产力格，不要金币、信仰格。区域潜力不变或变高。
- “成长优先”仍起作用：改前它和均衡选的城址在 7 / 12 个场景里不同，改后 8 / 12。
- 成长优先拿到的新奢侈品种类从 8 减到 5：奢侈品格多是金币、信仰、宜居度，地块部分按固定倍数后不如食物格值钱；奢侈品本身照旧按页签上的“宜居度”权重另算。

## 方案会怎样变

金币、信仰、科技、文化的地块（如有金币的海洋格、圣地附近的信仰格）被占的代价变小，区域更愿意放在这些格上；食物、生产力的格不变。权重行把某种产出调高，不再同时抬高这种产出的地块价值（原来调高科技也会让有科技的地块更难被占）。
