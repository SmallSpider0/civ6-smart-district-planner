# #350 波兰两座参照城的“新覆盖”：裁判没算已打钉的工业区（2026-11-08）

Issue：[#350](https://github.com/SmallSpider0/civ6-smart-district-planner/issues/350)。离线对比的玩家存档场景 `RP16`（克拉科夫）、`RP17`（彼得哥什）里，本模组自报的新覆盖是 0、1 座城，裁判算的是 6、7 座；覆盖权重 0 时裁判也是 6、7，本模组的方案不随覆盖权重变。2026-10-25 记进 [19-coverage.md](19-coverage.md) 实测一节，一直没查。

## 1. 结论：裁判多数了，本模组和场景导出都没错

两个场景来自同一个存档（`_Calyx` 的波兰，第 100 回合），作者给克拉科夫和彼得哥什各打了一枚工业区地图钉，两枚钉挨着。每个场景只规划其中一座城，这座城的参照区域（含它的工业区钉）从场景里拿掉，另一座城的钉照存档留着（tools/README.md 的 `RP`）。

- `RP16`（场景坐标）：留下的是彼得哥什的工业区钉 (15,13)，本模组把克拉科夫的工业区放在 (16,14)。(16,14) 6 格内的本方城市有 6 座，全部也在 (15,13) 的 6 格内。
- `RP17`：留下的是克拉科夫的工业区钉 (16,18)，本模组把彼得哥什的工业区放在 (15,17)，6 格内 7 座城，其中只有华沙不在钉的 6 格内。

设计第 19.2 节：“原有覆盖”是玩家已建的和已打钉的同类区域（被替换的旧钉除外）。本模组照此把钉算作已经覆盖，所以新覆盖是 0 和 1；裁判（`cmp_lib.lua` 的 `Covered`）原来只数已建区域（`Players[0]:GetDistricts()`），不看地图钉，所以“覆盖前”是 0，新覆盖 6 和 7。逐城核对：两种算法的差正好是钉覆盖的那些城，一座不多一座不少。

方案不随覆盖权重变也是对的：能覆盖到的城早被邻城的工业区钉覆盖，挪工业区换不来新覆盖（`RP17` 能多覆盖的华沙，权重 0 的方案已经够得着）。

场景导出（`tools/covscene.py`）照存档导出了这两枚钉，没错；“本城不算”（#91、#346、#349）与此无关：两座城各自被对方的钉覆盖。

## 2. 改法（只动测试工具，不到玩家手里）

- **裁判**：`CmpRun.Judge` 在把方案打成钉之前记下场景里原有的钉（`manualPinList`），`Covered` 在已建区域之外也数其中图标是区域的钉（`ICON_` 去掉后在 `GameInfo.Districts` 里），和设计 19.2 一致。方案自己的钉不在其中。
- **`refresh_results.py --check`**：原来只核对本模组自报的相邻加成（`stats.sdpGain`）等于裁判的；现在也核对自报的新覆盖（`stats.sdpCovered`，覆盖权重大于 0 时才有）等于裁判的 `coverageGain`，不等时列为 `REPORTED coverage …` 并退出码 1。这一条要是早有，2026-10-25 就会报出来。`tests/tools/test_refresh_results.py` 的新用例在旧代码上失败。

## 3. 重跑与核对

- 裁判改动只影响场景里有带覆盖半径的区域钉（工业区、娱乐中心、水上乐园）的：入库覆盖结果里是 `RP16`–`RP20`。生成的 `V`、真实的 `RC` 场景没有这类钉。
- `coverage_player.jsonl` 用新裁判重新打分（`node tools/compare.mjs --rejudge tests/compare/results/coverage_player.jsonl --out …`，再按原来的行序写回；方案不变）：`RP16` 覆盖前 7、后 7、新增 0，`RP17` 覆盖前 6、后 7、新增 1，与本模组自报的相同，作者布局也是 0 和 1；`RP18`–`RP20` 的娱乐中心钉让覆盖前后都从 0 变成 4，清单里没有工业区、娱乐中心，新增仍是 0。其余行的加成、合法性、覆盖逐个不变；这份文件上次打分早于裁判加上潜力产出等字段，重新打分后每行多了这些字段。

## 4. 测试（2026-11-08，变基到 #349 合并后的 `main`）

- `python3 -I -m unittest discover -s tests/tools`：通过；`test_refresh_results.py` 的新用例在旧的 `refresh_results.py` 上失败（自报 0、裁判 6 时退出码 0）。
- `refresh_results.py --check tests/compare/results/coverage_player.jsonl coverage_single.jsonl coverage_sdp.jsonl`（198 次）：方案全部不变，自报的加成、新覆盖与裁判全部一致。在 #349 合并前的代码上跑同一检查，`RP16`、`RP17` 已经一致，另报出 60 行自报的新覆盖比裁判少 1–2：#347 让规划了同类区域的城不计覆盖，裁判照常计入；#349 改回算本城后这些行都一致了。这说明新检查能抓到这类不一致。
- `refresh_results.py --check`（开发集 268 + 72 次）：方案全部不变，写入 `check_stamp.json`。
- 只改测试工具，没有游戏内测试。
