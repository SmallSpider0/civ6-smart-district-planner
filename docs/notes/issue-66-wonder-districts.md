# #66 需要相邻区域的奇观带上区域（2026-10-25）

调研（规则库里哪些奇观要相邻区域、其他规划器的做法、玩家攻略）和方案在 #66 的评论里。维护者 2026-10-25 定：方案 A，7 个待定问题都按建议。这里记实现。

## 规则

- 区域补在求解器里（`SDP_Multi.NewSession`），单城页选了奇观时也走它（只有这一座城），两个页签同一套规则。
- 奇观要相邻的区域从 `Buildings.AdjacentDistrict` 读；玩家有替换它的特色区域时补特色区域（罗马补浴场给吴哥窟）。要市中心的（紫禁城等）不补。
- 不补：任一参与的城已有（已建、为它打了钉：`SDP_City.PresentDistricts`）或计划里有（必建、自动加入）这个区域。别的、不参与的城有不算（坑 42：奇观只认建它那座城的区域）。
- 补给城市列表里第一座满足这些条件的城：
  - 玩家没在这座城的清单里把它点成“不建”（请求的 `Off`、`Offs[Key]`：只有存下来的“不建”算，默认就是不建的市政广场不算）；
  - 城里没有建成或打了钉的、计划里也没有与它互斥的区域（水上乐园与娱乐中心，`SDP_Rules.ExcludedBy`）；
  - 没到全帝国上限；
  - 城的候选格里至少有一格 DMT 和引擎都允许放它（`SDP_Overlay.CanPlace`，找到一格就停）。是否还有挨着它、能放奇观的格不预先查，放不下时照常列出。
- 补上的区域当作这座城的必建区域，算进它的“区域数量”（从候选里挑的个数随之少一个）。两个奇观要同一种区域只补一个。
- 全帝国限一个的区域已在别的城（`MAX_PER_PLAYER`）：补不了，奇观的原因是 `DISTRICT_ELSEWHERE`，写明在哪座城（`SDP_Multi.WhereBuilt`：已建的那格或钉所在格归属的城）。
- 结果：`result.Supplied = { { City, Type, Wonder } }`；补上的区域的方案条目和放不下时的条目带 `ForWonder`。

## 界面

- 单城页：选了奇观、城里又没有那个区域时，这一格显示“随奇观”（`SDP_UI.WonderNeeds`，规则同上，选中样式）。这个状态是根据选了哪些奇观算出来的，不存（#57 也不存区域状态）；点这一格从它自己存的状态往下切（候选 → 必建 → 不建），点成“不建”就不补。去掉奇观，格子恢复原状。
- 多城页：不改共用清单，否则每座城都会多一个。奇观标签下加一行（`MultiSupplyNote`）：求解前写“罗马斗兽场要挨着娱乐中心：求解时补给列表里第一座能放下的城”，求解后写补给了哪座城。想指定哪座城，就给那座城开自己的清单并设为必建。
- 结果行：补上的区域写“（供罗马斗兽场相邻）”；放不下时写“随罗马斗兽场补上的娱乐中心放不下”，奇观那一行照常写原因。

## 测试

- 离线 `spec_multi.lua`：罗马斗兽场补到列表里第一座城、挨着它放；共用清单里“不建”时不补、原因写明区域；第一座城自己的清单里“不建”时补给下一座；第一座城计划了水上乐园时不补给它；已计划时不补；只有城址参与时，大图书馆用城址自己补上的学院（原来放不下）。
- 离线 `spec_panel.lua`：经格子的点击回调检查“随奇观”的显示、求解后的标注、点成“不建”后奇观放不下且原因写明区域、去掉奇观后恢复；多城页的说明行。
