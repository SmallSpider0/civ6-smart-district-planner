# #327 测试基础设施

#327 调研后“建议直接做的”几项分三个分支做，各写自己的小节。

## 第 1、3 项：面板放回默认、页面装不下就失败（#325 一起修）

分支 `mac/test-reset`。只改测试、测试工具和面板里不改行为的测试入口与自检；方案和面板外观不变。

### 做法

- **`SDP_Panel.Defaults()`**：停掉计算、退出窥视、清掉“结果已算好”的标记和地图预览，三个页签各调自己的 `Defaults`，切回单城页，重排窗口。面板开着还是关着照旧；本模组的钉不动（撤销照旧由测试自己做）。
  - 设置（权重、开关、档位、预设、折叠、单城和多城的奇观、选城址的数量和距离、区域状态等存进存档的项）走存档读回的同一条路：`SDP_Settings.Keeper` 加 `Defaults()`，就是 `Decode(nil)`（存档里什么都没有时）再 `Apply`。先 `Restore` 一次再套默认，免得之后第一次读存档把改过的设置又读回来；套完 `Remember` 写回存档。没有另写一套默认值。
  - 不进存档的状态由各页签清空到模块初值：单城页的城（回到选中的城或首都）、区域状态、各城的数量、好位置图；选城址页翻转过的勾；多城页的共用清单、各城自己的清单、奇观放哪座城、中心城和参与城的开关。三页的方案都清掉。
- **`SDP_UI.CheckFit(name, page, body)`**：三个页签的 `FitPage` 排完版后调一次（多城页在“城的格子缩行”循环之后，中间几次不算）。主体（底下是求解、打钉按钮）比页面高时经 `SDP_UI.Log` 写一行 `SDP_LAYOUT_OVERFLOW <页签>: the body N does not fit the page M`；隐藏的页签不查（切过去时会重排）。
- **`run_tests.py`**：每个文件的 `@setup` 之前在 `SDP_Panel` 状态执行 `SDP_Panel.Defaults()`（单独一次 exec，不计入 `@max_seconds`）。测试输出里出现 `SDP_LAYOUT_OVERFLOW` 时，把它后面那项测试记为失败；放回默认时出现的记为这个文件的失败；`SDP_Panel` 状态里的 fixture 输出它也算 fixture 出错。`--shortest-window`：每个文件开头把 `SDP_UI.WindowHeight` 换成返回 `WINDOW_MIN` 再 `FitWindow`，整个运行结束（含出错）后换回、按屏幕重排；`--rulesets` 会传下去。
- **`shots.py stage`**：执行脚本前先撤销本局本模组打的钉（撤到底），再 `SDP_Panel.Defaults()`；`--as-is` 跳过。`tests/shots/sites.lua` 去掉逐个设回默认状态的那行；`multi.lua` 不再沿用选城址页留下的方案，自己算（与 `stage sites` 同样的设置）。

### 删掉的手写重置

- `test_ui.lua`：`Reset()` 改为先 `Defaults()`，删掉重设权重、清除开关、地块、档位的几行；删掉 #323 加的 `ClearMulti()`（切两次“提醒钉”来清多城方案），改为断言 `Reset()` 后多城页没有方案；#320 那项结尾的逐项还原换成 `Defaults()`。
- `test_features.lua`：`Reset(districts)` 改为先 `Defaults()`，删掉切页签、清奇观、关“替换”、设档位；`Finally` 里关好位置图、关“替换”、清奇观换成 `Defaults()`；覆盖范围那项的 `Solve` 同样改。
- 没删的：其余文件测试之间的还原（`SetTier(tier)`、`SetExisting(id, nil)`、`ApplyPlan({})` 这类）。`Defaults` 只在每个文件开头自动调，同一文件里后面的测试仍靠前面的测试还原；逐个改成 `Defaults()` 要逐项看它是否依赖前一项留下的状态，这次不动。`test_improve.lua` 的 `Setup()` 找的是地图上的格，不是面板重置。

## 第 2 项：一帧工作量看门狗

分支 `mac/frame-watchdog`。只改测试和测试工具。

**做法**（`tests/offline/watchdog.lua`、`tools/offline_tests.mjs`，用法见 tools/README.md“offline_tests.mjs”）

- 本工具给每个 Lua 状态装一个计数钩子（`LUA_MASKCOUNT`，每 1000 条指令回调一次），累计虚拟机指令数。协程继承钩子（fengari `lua_newthread` 复制 `hook`、`hookmask`），所以任务的协程里也数。
- `SDP_Task` 一加载（`include` 之后）就把 `SDP_Task.Step` 包一层：每次 `Step` 是面板任务的一帧，量这一帧的指令数，记下这个测试最长的一帧；超过 `SDP_Watchdog.LIMIT` 时测试失败，写明任务（`planner (MULTI)` 这样的名字和页签）、第几帧、在哪个函数里超的。
- 超了就停：一帧开始时给钩子设上限，过了上限，钩子在任务的协程里报错（只在协程里，`Step` 自己在主线程上的收尾照常做完，覆盖层照常收起），`Step` 把任务记成出错结束。#307 修之前那种一帧 482 秒的跑飞循环几秒内就失败，不会把整套测试拖住。
- 只量经 `SDP_Task` 分帧的计算；测试里直接调 `SDP_Solver.Solve`、`SDP_Multi.Solve` 的同步求解不量（游戏里它们也不在一帧里跑，面板总是经任务）。
- 测试自己定了比面板最大的还大的配额时（`SDP_Panel.RunTask(5000)`），那一帧在游戏里相当于几帧，上限按 配额 / `SDP_Task.MAX_QUOTA` 放大。`spec_citychips` 的 “all cities (issue 142)”（9 城加 3 个城址，分组求解，`RunTask(5000)`）最长一帧 1.10 亿条（第 4 帧，放大后的上限 1.5 亿），不放大时在第 3 帧超限，停在 `SDP_Search:Beam`，和 #331 是同一处。
- opt-out：`SDP_Watchdog.OptOut("原因")`，和 `SDP_Invariants.OptOut` 一样，在测试里调用只管这个测试，在文件顶上调用管整个文件。现在没有测试用它。

**上限怎么定**：`LIMIT` = 2000 万行 × 每行约 3 条指令 = 6000 万条，约合游戏里 0.2 秒。

- 调研（#327 技术细节）：fengari 约 450 万行/秒，比游戏慢 20–27 倍，所以游戏里 0.2 秒约等于这里 2000 万行；现有测试两次 `Tick` 之间最长 1460 万行（`spec_pools`）。
- 每行几条指令（2026-11-07，本机，同时开行钩子和每条指令的计数钩子）：`spec_pools` 2.96、`spec_sites` 3.83、`spec_multi` 2.67。取 3。
- 指令速度（只开看门狗的钩子，本机有别的任务同时跑）：`spec_pools`、`spec_sites`、`spec_task` 约 920–970 万条/秒，`spec_many_wonders` 830 万条/秒；`spec_max_scale` 的选城址那项只有约 470 万条/秒（表操作多）。所以 6000 万条在这里是 6–13 秒，按 20–27 倍折合游戏里 0.2–0.6 秒：指令数是确定的、不随机器快慢变，但和游戏时间的换算只准到两三倍以内。
- 面板正常的一帧（`SDP_Task.MAX_QUOTA` = 2000 单位，目标 1/30 秒）离上限很远：见下面各用例的最长一帧。

**开销**：整套离线测试（第二台机器，一格）：改前 `main`（bb7c3df）565 秒；同时跑的加看门狗那次，除 `spec_citychips`（那次在它上面先超限停下）以外的文件 508 → 501 秒，在误差内。之后单独跑的一次（加 `spec_max_scale.lua`）共 565 秒，其中 `spec_max_scale.lua` 77 秒。计数钩子每 1000 条指令才回调一次，fengari 每条指令本来就查一次钩子掩码，所以几乎不花时间；行钩子（调研用的）要慢得多。

**最大规模的用例**（`tests/offline/spec_max_scale.lua`）：经页签自己的求解按钮开始，之后每帧调一次面板的 `SetUpdate` 回调，帧长 20 毫秒（短于目标帧长，任务的配额涨到 `MAX_QUOTA`，是游戏里会给的最大一帧）。只查跑完、方案合规（方案不变量）和看门狗，不查方案好坏。

## 第 4、6 项：设置对账、三个页签的“继续优化”

分支 `mac/reconcile-tests`。只改测试；面板里加了三个只读的测试入口（`SDP_Settings.Keeper` 带出 `Fields`、`Values`、`Apply`，`SDP_PageKit` 带出 `Switches`，三个页签 `P.Kit`），方案不变。

### 对账测试 `tests/offline/spec_reconcile.lua`

- **设置从哪来**：每个页签自己的设置表（`SDP_PageKit` 的 `Keeper.Fields`，就是写进存档的那张：权重列、开关、档位、奇观、选城址的数量和距离等），不在测试里手写清单。新加一个存进存档的设置，测试自动多查一项。
- **怎么改**：都经控件自己的回调：权重点它那一列的箭头，开关点勾选框，档位点下拉框，折叠点折叠按钮，奇观从下拉框加、点标签去掉，选城址的数量、距离、区域数量点加减按钮，密铺点勾选框（密铺的距离在密铺开着时点距离按钮），区域状态点区域格（Codex 在 PR #333 指出原先这些走 `Keeper.Apply`，回调坏了也测不出；临时弄坏数量或密铺的回调，测试会失败）。没有控件、只在存档里的设置写进测试的 `SAVE_ONLY` 并写明原因，目前没有；改回也走同一条路（“替换”开关的 `OnChange` 要再跑一次，否则各城的数量跟着变，后面的比较全是“变了”）。
- **比什么**：点页签的“求解”按钮，记下求解器收到的东西，和改之前比：
  - 请求：页签调用的入口（`SDP_Solver.Solve`/`SolveScan`、`SDP_Multi.SolveNow`、`SDP_SiteSolver.SolveNow`）的参数；
  - 搜索输入：每次 `SDP_Search.New` 的参数（不含 DMT 棋盘）。页签的权重表会原样一路传下去（如 `Appeal.Weights`），所以请求里的 `Weights` 换成代理，只记搭搜索时（`New` 和紧接着的 `Singles`）真正读了哪几个键和它们的值；
  - 选城址按城址对齐（换了权重城址会挪，只比两次都评过的城址）；
  - 好位置图：它交给 DMT 的权重和找出的格子、分数。
- **为了快**：城市的求解在 `Singles` 之后就停下（只比输入，不比方案）；选城址给每个城址的搜索一个空壳。整份约 30 秒（第二台机器）。
- **五条路**：单城页不勾奇观（`SDP_Solver`）、单城页勾奇观（`WonderRequest` → `SDP_Multi`）、多城页、选城址页、好位置图。世界里两座城挨得够近能换格，有一枚本模组的钉（“替换”有东西可替），工业区从改良设施拿相邻、住宅区的住房跟魅力走，所以每个设置都有机会起作用。
- **结果**：每项设置要么到了搜索输入；要么在表里写明为什么不用：

| 路 | 不用（求解器收到的完全一样） | 进了请求、没进搜索 |
|---|---|---|
| 单城（两条路）、多城 | 折叠：只折起设置 | 提醒钉：只决定打钉时放不放提醒钉 |
| 选城址 | 折叠 | 住房、宜居度、战略资源、魅力的权重（城址分里另算，不在区域摆法的搜索里）；新城数量、两城距离、密铺、密铺距离（决定城址在哪，每个城址的搜索不变） |
| 好位置图 | 折叠、提醒钉、改良设施两个开关、档位、奇观 | 地块、距离、住房、覆盖范围的权重（#324 定了好位置图只看相邻加成） |

  另有一张“多城页缺的设置”：多城页没有“允许砍伐”开关，总是允许（`docs/notes/16-stages9-12.md`）。单城页和多城页其余的设置一致。
- **会失败的旧状态**（临时改代码验证过，没提交）：`WonderRequest` 不抄 `Coverage`、`Distance` → 单城勾奇观那条路的覆盖范围、距离两项失败；多城页请求不带 `Improvements` → 改良设施两项失败；选城址请求不带 `Distance` → 距离失败。新加一个开关而三处都没接，它会落在“不用”或“没进搜索”而表里没写，同样失败。
- **好位置图和求解的对比**：同一份文件最后一项。表里“好位置图不用、单城求解用”的设置都要列进 `HEAT_NEUTRAL`（地块、距离、住房、覆盖范围为 0，改良设施两个开关关）或 `HEAT_ANY`（档位：只放一个区域时哪一档都找得到最好的格；奇观：不勾），然后只放商业中心，比好位置图的第一名和求解的那一格。这张地图上商业中心最好的格是城还没拥有的，距离开满时求解会换一格（测试里先确认这一点，免得比较测不出东西），好位置图的分数不变。游戏内 `tests/test_features.lua` 的同一比较改为同样设这几项（原来只设了距离和地块），注释指向 `HEAT_NEUTRAL`。

### 继续优化 `tests/offline/spec_continue.lua`

- 单城页（精细档，分帧那一支）、单城页勾奇观、多城页、选城址页，各自点“求解”“继续优化”“取消”按钮；帧由面板自己挂的 `SetUpdate` 函数一帧一帧地调（不经 `SDP_Panel.RunTask`）。
- 查：求解和继续优化都跑了不止一帧；运行中“取消”显示、“继续优化”隐藏、不能打钉；跑一帧后取消，显示的还是继续前的方案，能打钉、能再点继续优化；再点一次跑到底：在帧数上限内结束、更新函数被清掉、显示的是这次继续的新结果、分数不低于继续前、按钮恢复。
- 结果：四条路都通过，没有发现问题。会失败的旧状态（临时改过）：多城页继续优化的完成回调不保存结果 → “显示的是这次继续的新结果”失败；单城页继续优化开始时清掉结果 → “取消后仍显示方案”失败。
- 只在离线测：分帧和按钮是面板自己的 Lua，离线替身里能走到底；游戏里的测试钩子 `RunTask` 不经 `SetUpdate`，在游戏里测不到更多。
