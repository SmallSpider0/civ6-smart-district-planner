# #226 选城址页打开密铺后进度停在 24%（2026-11-03）

来源：创意工坊玩家，v1.6.x（当时密铺默认 12 座），没说文明、地图大小、最远距离。

## 1. 结论

没有复现出“停住不动”。离线和游戏里，密铺 12 座都能算完；找到的是一处会让进度长时间停在同一个数的工作量：

- 候选城址的范围是“新城数量 × 最远距离”（`SDP_Sites.Candidates` 的 `K * D`）。密铺 12 座、距离 5 时是 60 格，几乎整张地图都算候选。
- 旧代码先给每个候选算粗评分（`SDP_Sites.Coarse`），再用全部候选的周边建棋盘（`SDP_Sites.Board`），之后才开始精评。这两步每个候选只记 0.2 个工作单位，进度条几乎不动，分帧也按很少的工作量切。
- 密铺只比较“离已有城市和已放城址最近的那一圈”候选，绝大多数候选的粗评分用不上。

## 4. 分支 `mac/dense-sites-stall` 上的改动（没开 PR，等主会话定）

- `SDP_SiteSolver`：密铺时候选只在要比较时才算粗评分（`Session:CoarseOf`）；贪心放城先找最近的距离，再在同样近的候选里比粗评分，结果和原来的比较顺序相同。
- `SDP_Sites.BoardFor` / `SDP_Board:AddFixed`：棋盘只放精评过的城址周边的固定区域和钉，在精评前加上；一个城址的区域和它们的邻格都在它 4 格内，分数不变。平时模式也用它。
- `SDP_Task.Extra`：扫图、粗评分、贪心放城按实际工作量记单位，同时把预计工作量加上同样多，进度不会因此提前到 99%；测速不算它们。
- 游戏内探针 `tests/bench/i226_dense_probe.lua`（`run_tests.py -v`，打印候选数、粗评数和方案）。
- 测试：`spec_sites` “issue 226: dense packing scores only the candidates it compares”（旧代码上粗评 928/928，失败），`spec_task` “extra work paces the frames and grows the estimate”。
