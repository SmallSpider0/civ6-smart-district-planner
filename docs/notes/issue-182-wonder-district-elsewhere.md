# #182 为奇观补的区域：别的城本来就挑了同种区域时改补给它

## 问题

多城页选了要挨着某种区域的奇观（罗马斗兽场要挨着娱乐中心），参与的城都没有这种区域（已建、已打钉、必建）时，#66 把它补给列表里第一座能放的城，当必建，算进那座城的数量；#180 起奇观一定挨着补的那个。面板默认所有占名额的区域都是候选，所以另一座城常常本来就会从候选里挑一个娱乐中心。这时补的那个是白补：奇观可以挨着那座城挑的，第一座城空出的名额能挑别的。

## 考虑过的做法

1. **补的区域在搜索里变成可有可无**（#180 的笔记里说的“新的一种槽”）：不补，奇观挨着任何一座本城挑的同种区域即可。先试了最小的版本：不补，奇观只要求本城有同种区域（区域都从候选里来）。在 OM01（罗马、两座城、斗兽场）上，搜索先按模型分挑每座城的候选组合，娱乐中心本身没有相邻加成，排不进前几名；奇观最后放，没有娱乐中心就放不下。补放（`Session:Repair`）把每座城没挑的娱乐中心候选也放上，两座城都变成 4 个区域（数量 3），分数也更低（10.0 对 12.85）。要让搜索在挑候选时就知道奇观要什么，得改候选组合的排序、补放和换候选的逻辑，改动大，奇观也可能丢。没有继续。
2. **补给另一座城再算一遍，留更好的**（采用）：先照旧补给第一座城求解；如果最好的方案里另一座城从候选里挑了同种区域，就把补的区域改补给那座城（它挑的那个变成必建、奇观挨着它），第一座城的名额回到候选里，整个请求再求解一次，两个方案比：放下的奇观多的、放下的区域多的、分数高的胜，相同时留第一个。
   - 两次都是现有的、已经测过的搜索：奇观总挨着一个必建的区域，不会因为改动而放不下。
   - 不劣于改前：第一次求解就是改前的结果，第二次只在更好时才换。
   - 只在问题出现的情况下多花时间（另一座城确实挑了同种区域），约多一倍。

“可有可无”的解空间其实等于“补给每一座可能的城”这几种解空间的并集：任何奇观放下的方案里，总有一座城的同种区域挨着奇观，把补的区域给那座城就得到它。做法 2 只试最可能的那一座（改前方案里挑了它的城），而不是每一座都试。

## 顺带修的

`Session:Repair`（奇观或区域放不下时腾地方重放）把“奇观要挨着的同种区域”全部拿来重放，包括某座城没从候选里挑的那些，重放后它们都放上了，那座城的区域就超出每城数量。现在只取方案里已有的（必建的、或这座城挑了的）。上面做法 1 的实验就是这样发现的；改前的代码在奇观被挤掉、要补放时也会这样（离线测试在旧代码上复现：第二座城 2 个，数量 1）。

## 另一处要注意的：两次求解共用一张地图图层

两次求解的棋盘（`SDP_Board`）都往同一个 DMT 图层（`SDP_Overlay` 的 Layer）上放东西。第一次求解结束时它的最后一个布局还留在图层上，第二次求解就把这些区域当成邻居算；留下第一个方案时，它的结果又是在第二次求解留下的区域旁边算的（OM06 大图书馆：搜索里 30，结果写 33，`Stats.Mismatch` 为真）。改法：第二次求解前清掉第一个棋盘，选完后清掉没选的那个。`spec_wonder_host.lua` 查第二次求解开始时和结束后图层上什么都没有；不清时失败。

第一次跑的实验（本机，2026-11-02 23:36 起）用的是没清图层的代码，结果作废，下面是修好后重跑的。

## 实验

`tests/compare/probe182.lua`：面板的默认请求（场景里的城都参加、共用清单、所有占名额的区域都是候选、每城再规划 3 个、计入地块），选一座奇观，改前（只算一次）和改后（`SolveNow`）各求解一次，同一进程里先后跑（同样的输入连跑两次结果完全相同，OM06、OM11 核对过）。开发集多城场景 `OM01`–`OM16`、`M01`–`M12`，罗马斗兽场、大图书馆各一遍，共 56 组，STANDARD 档。第二台机器跑：

```
python3 -I tools/remote.py run i182-sweep --slots 6 -- sh -c '... | xargs -P 6 -L 1 sh -c "node tools/compare.mjs --probe tests/compare/probe182.lua --arg \"$0 $1\" ..."'
```

结果在 `logs/remote/i182-sweep.txt`（不入库）。

| | 场景数 |
|---|---|
| 补了区域 | 56（全部：默认清单里这种区域只是候选） |
| 另一座城挑了同种区域，算了第二遍 | 25（斗兽场 9，大图书馆 16） |
| 第二个方案更好、换成它 | 13（斗兽场 4，大图书馆 9） |
| 比改前差 | 0 |

- 换了的 13 组目标值平均 +2.04（+1 到 +4.5，平均 +11%），例如 OM08 印度尼西亚斗兽场 14.5 → 19，M10 埃及大图书馆 18 → 22；每座城仍是 3 个区域，奇观都放下了。
- 留下第一个的 12 组目标值不变（第二个方案不比它好，平局留第一个）。
- 代价：算了第二遍的 25 组 DMT 调用是改前的 1.74–2.40 倍（平均 1.99）；另外 31 组不变。只比 DMT 调用次数，没有比耗时（今晚本机过热降频，见当晚的说明）。

所以做法 2 定下来了：在问题出现的场景里约一半能换到更好的方案，没有变差的，代价是这些场景多算一遍。
