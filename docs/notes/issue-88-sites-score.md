# #88 选城址计分：各项折成每回合点数（2026-10-26）

决定：[#88 合作者已定](https://github.com/SmallSpider0/civ6-smart-district-planner/issues/88)（方案 A），资源部分按 [#86](https://github.com/SmallSpider0/civ6-smart-district-planner/issues/86) 已定的公式，住房按 #91 的方案 B。

## 1. 公式

```
城址分 = 区域 + 地块 + 地貌 + 住房 + 奢侈 + 战略 + 魅力 − 可用格不足扣分
```

每一项先算出“每回合相当于多少点产出”（下表），再按固定规则折成分数（第 2 节），最后乘这一项自己的权重（页签上的区域、地块、地貌、住房、奢侈、战略、魅力，默认 1，魅力默认 0）。产出按地块的固定倍数折算（食物、生产力 1，科学、文化 5/6，信仰 1/2，金币 1/4，`SDP_Land.PLOT_WEIGHTS`），再乘页签上这种产出的权重。

经过：第一版（2026-10-26）只折成每回合点数，例子里地块和地貌占八成以上，合作者没通过（“没解决仍被地块和地貌淹没的问题。目标是希望每个因素的权重差不多”）。第二版按这次的候选城址折成 0–10 分（最好的 10、最差的 0），合作者也没通过（2026-10-27：“不要用候选城，直接给每个维度一个固定的打分规则，使得多次打分一致。可以多生成一些地图统计各项数值”；住房、奢侈、战略要保留原来的分级算法，不能变成有或没有）。现在是第三版：固定规则。

| 项 | 怎么算（代码） |
|---|---|
| 区域 | 计划区域在城址周围最好摆法的相邻加成（DMT），和单城页一样 1 点产出算 1 分，乘产出权重和区域权重（`SDP_Sites.Board` 的 `AdjacencyWeights`）。距离成本也在这里扣。 |
| 地块 | 区域占格后，最好 P 格每回合的产出（修上最好的改良）。每格按“留着”或“砍掉/收获后”取较好的那种的每回合产出；P = 3k − 2（`SDP_Sites.LandParts`、`SDP_Land.WorkedParts`）。 |
| 地貌 | 3 环内每格的砍伐、收获一次性产出 × 增长倍数 ÷ 50 回合，只算这格被砍掉/收获时：城市不耕作的格都算；耕作的格只在砍掉更值时算（`SDP_Land.PlotValues` 的第三个返回值是留着时放弃的那部分）。 |
| 住房 | 住房权重 × [HV(该城址住房) − HV(无水城址住房)]，HV 按 #91 方案 B（新城按人口 1）。 |
| 奢侈 | 新种类的第一份：min(资源的宜居度 4, 方案完成后的城市数)；其余份数每份 1，最多卖给“已相遇、还没有这种资源的主要文明”个数（玩家自己多出的份数先占）。 |
| 战略 | 每格 时代分 × 种类分。时代分：揭示科技在玩家所在时代或前一个时代为 2，更早为 1；种类分：新种类的第一格 2，已有但不够用（风云变幻：库存不到上限 25% 或每回合收入 ≤ 0）1.5，其余 1。 |
| 魅力 | 魅力权重 × 可建区域格的平均魅力（还没有折成每回合的说法，默认 0）。 |

- 地块 + 地貌 = 原来的“耕作 + 地貌”之和的同一种算法：每块耕作的格取 max(留着的每回合产出, 砍掉后的每回合产出 + 一次性产出 ÷ 50)，不耕作的格只算一次性那部分。拆开只是为了显示和分开加权。
- 一次性产出按 50 回合摊开（原来 20）。其他游戏速度：游戏把砍伐、收获的产出按速度放大，回合数按决定也按同样比例放大，两者抵消，所以代码里各速度都是 50。
- 一次性产出仍按科技市政进度增长：×(1 + 9 × 进度)，和单城页一样（`SDP_Land.ONE_TIME_GROWTH`）。
- 单城、多城页的地块模型不变（一次性产出仍按 20 回合）。

## 2. 折成分数：固定规则（第三版，2026-10-27）

```
一项的分数 = 10 × 这一项的每回合点数 ÷ 好城址这一项的典型值 × 这一项的权重
```

“好城址的典型值”（`SDP_Sites.REFERENCE`）取统计地图上精评城址这一项的第 90 百分位左右，按单位折算，所以计划区域多少、科技进度不同时规则不变：

| 项 | 10 分对应 | 统计（第 90 百分位） |
|---|---|---|
| 区域 | 每个计划区域相邻 +4 | 古典 4.0、文艺复兴 3.3、全部科技 4.0 |
| 地块 | 每块耕作的格 4.3（开局）到 7.2（全部科技），按科技市政进度线性 | 古典 5.3、文艺复兴 5.1、全部科技 7.3（中位数 4.8、5.0、7.0） |
| 地貌 | 一次性产出每回合 5 × 增长倍数；一块树林砍掉 20 生产力 ÷ 50 回合 = 0.4 × 增长倍数，所以一块树林 0.8 分，与时代无关 | 每单位增长倍数：古典 3.6、文艺复兴 6.0、全部科技 5.6 |
| 住房 | 比无水城址多 3 点住房（河边、湖边） | 3（有水源加成的城址占 14–23%） |
| 奢侈 | 一种新奢侈资源，4 座城都用上 | 古典 6、之后 3（方案完成后 3 座城时新种类记 3） |
| 战略 | 一种新战略资源的第一格，玩家所在时代或前一时代揭示（2 × 2） | 古典 4、文艺复兴 2、全部科技 5 |

- 统计：48 张生成的选城址地图（`ZS01`–`ZS48`，12 种文明和地形 × 4 个种子；玩家的科技和市政分别到古典、文艺复兴、全部，每种文明和地形三个阶段都有），每张地图默认权重精评的 40 座城址，共 1920 座；各项按每回合点数（`Raw`）输出。命令：`node tools/compare.mjs --probe tests/compare/probe88.lua --arg 'ALL <场景>'`，在第二台机器上 2 个格子跑完约 25 分钟，结果在 `logs/remote/i88-calib.txt`（不入库）。
- 生成地图的玩家原来总是全部科技（一次性产出是开局的 10 倍、改良设施吃满科技加成、所有战略资源可见），只用这种地图定规则会偏，所以统计地图按时代给科技（`cmp_game.lua` 的 `era`，玩家所在时代也跟着设）。
- 按这套参考值，1920 座城址默认权重下各项占总分：区域 20%、地块 29%、地貌 18%、住房 5%、奢侈 14%、战略 13%。住房占得少是因为大多数城址没有水源加成；地块各城址都在 8–9 分上下（同一张图上标准差 0.6 分），占分不少，但很少决定选哪座；奢侈、战略在城址之间差得最多（标准差约 3.5 分）。48 张图里 32 张排第一的城址和第一版不同。
- 可用格不足的扣分改为每缺一格 5 分。
- 距离成本按区域的同一个系数折成分数。
