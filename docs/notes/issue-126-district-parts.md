# #126 单城、多城页：每个区域的分项、每座城的小计、按产出的相邻加成（2026-10-27）

DracoYus 2026-10-27 定：三项都做，地块损失按“去掉这个区域后地块分回来多少”分到每个区域，对不上的差额写在汇总行的悬停里。选城址页在 #88（PR #125）里做，这里不动。

## 玩家看到的

- **区域行悬停的第一行**：“本区域：加权相邻加成 +4（地块 -2.5；距离 -1）”。括号里的项跟汇总行一样，按开着的权重列：地块、距离开着时总写；住房、覆盖只在这个区域的份额不为 0 时写。单城、多城页都有。
- **多城页每座城一行**（原来的“新区域加权相邻 +X”）：现在是这座城各新区域分项之和，“新区域加权相邻 +X（地块 …；距离 …）”，悬停说明它是怎么来的。
- **汇总行悬停**最前面加两行：
  - “相邻加成按产出：科+6 文+3 ……；乘权重后：……”，乘权重后的各项加起来等于汇总行的加权相邻加成；
  - “不在各区域分项里的部分：已有区域 +1；地块 -0.5 ……”，只列不为 0（绝对值 ≥ 0.05）的项，全为 0 时这行不出现。

## 怎么算（都是求解器排序用的数，不另做近似）

方案分 `Gain = Adjacency + LandDelta + CostDelta + CoverageDelta + AppealDelta`（`SDP_Solver.lua`、`SDP_Multi.lua` 的 `PlanFor`）。`Search:Breakdown`（`SDP_Search.lua`）在算完这几项后：

| 项 | 每个区域的份额 | 剩下的（`Rest`） |
|---|---|---|
| 相邻 | DMT 给这个区域的加权分 `item.Score` | 锁定钉、已建区域的分变化 `Σ(After − Before)`（就是结果里“已有区域 加权分 3 → 4”那几行） |
| 距离 | 这个区域自己的 `-Costs[i]` | 0（本来就是逐区域相加） |
| 地块 | `LandDelta(方案) − LandDelta(去掉这个区域)` | `LandDelta − Σ份额` |
| 住房 | `AppealDelta(方案) − AppealDelta(去掉这个区域)` | 同上 |
| 覆盖 | `CoverageDelta(方案) − CoverageDelta(去掉这个区域)` | 同上 |

“去掉这个区域”= 布局里这个槽位设为 0，其余不动，用同一个 `Search:LandDelta` / `AppealDelta` / `CoverageDelta` 重算（`Search:SlotParts`）。所以每个区域的地块份额是真实的变化量；几个区域抢同一批好地块（城市只耕作最好的 P 格，去掉一个区域时第 P+1 格补上来）时，份额之和和合计对不上，差额进 `Rest`。

按产出的相邻加成 `YieldAdjacency` = 各新区域的 DMT 产出 + 已有区域产出的变化（未乘权重）；`YieldWeighted` = 乘权重后，各项之和等于 `Adjacency`。

多城每座城的 `Cities[p].Parts` = 归这座城（`Session:OwnerOf`）的区域的份额之和；`Parts.Adjacency` 等于原来的 `Cities[p].Gain`。已有区域的变化、份额对不上的差额只在方案层面（汇总行悬停），不分到城。

代价：每套方案多算 K 次地块、住房、覆盖（K = 放下的区域数），只在报告方案时算，不影响搜索。

## 测试

- `tests/offline/world.lua` 的 `World.CheckParts`：每个区域的份额 + `Rest` = 方案各项；各项之和 = `Gain`；`YieldWeighted` 之和 = `Adjacency`；多城每座城的小计 = 它区域的份额之和、小计的相邻 = `Cities[p].Gain`。
- 调用它的用例：`spec_solver`（新用例 “issue 126”：锁定的商业中心钉的变化进 `Rest.Adjacency`；地块份额 = 去掉该区域后重算的差；只有一个区域时没有剩余）、`spec_appeal`（保护区独占地块和住房；多城住房）、`spec_coverage`（工业区独占覆盖）、`spec_multi`（多套方案）、`spec_panel`（单城区域行悬停第一行、汇总悬停的按产出一行；多城每城小计行和区域行）。
