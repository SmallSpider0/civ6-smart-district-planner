# #191 密铺时新城数量不变（2026-11-02）

Issue：DracoYus，“密铺模式新城数量不变”。理由：一次规划 12 座城，等开拓者一个个造出来，局势早变了，能照计划建的没几座；地图探索后结果也会不同。建议一次少放几座，让玩家多次选城址。

决定（代理按 Issue 自己定，合作者在 #87 里定的“密铺默认 12”由他本人在这里收回）：新城数量平时和密铺共用一个数（默认 3），打开密铺时不变；密铺时最多仍可调到 12，关着时最多按 6 座用（数记着，再打开密铺时回来）。开关改名“密铺：新城挨着放”，“新城数量”加悬停提示。

## 1. 代码

- `SDP_PageSites.lua`：去掉密铺自己的数 `m_dk`（存档键 `DK`，旧存档里的值读档时忽略）；`K()` = `min(m_k, MaxK())`，`MaxK()` 密铺 12、平时 6；存档键 `K` 的上限改为 12。最远距离仍分开（`DD`，#87 定的）。
- 求解器没改：`SDP_SiteSolver` 的密铺本来就以 K 为上限。

## 2. 别人怎么做、玩家怎么铺

- Empire Planner：新城数量默认 3，0–6（`reference/ep/ui/ep_panel.lua` 的 `numNewCities`）；没有密铺。AMT、DWP 不选城址，只用玩家打的城市中心钉。
- 玩家：开拓者一个一个造，常见说法是第一个开拓者在首都 3–4 人口时出，之后平均十几到二十回合一座城；50 回合 3–5 座、100 回合 8–10 座是常见目标（Steam、CivFanatics 的讨论和攻略）。一次 12 座相当于 100 回合以上的计划。

## 3. 离线对比

12 个 `C` 场景（中期首都），标准档，面板默认的区域格：

```
python3 -I tools/sdplock.py heavy i191-cmp -- node tools/compare.mjs -s '^C[0-9]' -p sdp --add sdp:STANDARD_K3_GRID,sdp:STANDARD_DENSE_K3_GRID,sdp:STANDARD_DENSE_GRID --only sdp:STANDARD_K3_GRID,sdp:STANDARD_DENSE_K3_GRID,sdp:STANDARD_DENSE_GRID -j 4 --out logs/i191-cmp.jsonl
```

| | 平时 3 座 | 密铺 3 座 | 密铺 12 座 |
|---|---|---|---|
| 放下的新城（合计） | 36 | 36 | 144 |
| 违规 | 0 | 0 | 0 |
| 每座城的裁判城址分 | 32.8 | 31.8（−3%） | 28.5（−13%） |
| 每座城与本方城市重叠的格 | 6.9 | 7.8 | 9.9 |
| 求解耗时中位数（离线秒） | 71 | 79 | 124 |

- 密铺 3 座的城址只有 3/36 个正好也在密铺 12 座的方案里，20/36 个离 12 座方案的某个城址不超过 1 格（按奇数行右移的六边形坐标算）。也就是说，12 座的方案为了塞下后面 9 座，前几座的位置跟着让；一次只要 3 座时给的是另外的位置，每城分也更高。
- 密铺 3 座比平时 3 座每城低约 3%、重叠多一点：城挨得更近，留出后面的地方。
- 耗时：这次运行因别的会话占用游戏被暂停 7 次（`sdplock` 报告计时不可用），C04–C06 几行是几百到一千多秒；中位数只作参考。密铺的精评预算（`DenseRefined`）不随 K 变，所以 3 座的密铺并不比平时 3 座快。

耗时是 2026-11-02 夜里在散热不好的 MacBook 上测的，只看倍数。结果文件只在 `logs/`，不入库。
