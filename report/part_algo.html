A.1增量 + 记忆评估（SDP_Board）

DMT 给一个区域打分只看它的格子和周围 6 格，所以分数由三样决定：区域类型、格子、6 个邻格上规划了什么。挪动一个区域时，只有新旧位置周围的区域要重新取分；取分先查记忆，查不到才调用 DMT。

伪代码 
function 分数(区域, 格)
    键 = (区域.类型, 格, 邻居编码(格))       -- 6 个方向各一位：邻格上规划的对象
    if 记忆[键] 存在 then return 记忆[键] end
    在假想钉层上摆好这一局面；清 DMT 的地块缓存
    记忆[键] = Σ 权重[产出] × DMT.GetBonusYields(区域)[产出]
    return 记忆[键]
end

function 放置(槽, 新格)                    -- Board:Put
    受影响 = {槽} ∪ 旧格 6 邻格上的对象 ∪ 新格 6 邻格上的对象
    for 对象 in 受影响 do 总分 = 总分 − 旧分[对象] + 分数(对象, 对象.格) end
end

A.2单城搜索管线（SDP_Search）

先用便宜的线性模型在很大的范围里挑出一批好布局，再用 DMT 精确评估，最后用局部搜索和“拆一片再重放”修正模型的偏差。模型只决定往哪里找，最终分数都来自 DMT。

模型分 = 各区域单放分 + 相邻两区域之间的互惠 − 占掉好地块的损失，只用来排序。地块损失：k 个特色区域需要人口 P = max(人口, 3k − 2)，城市耕作最好的 P 块地，一块地被占的损失是它的产出减去第 P+1 好的地。

从候选里挑：给出区域数量后，多出必建的部分从候选里挑。

距离成本、自动区域、提醒钉：距离成本是每个候选格一个固定扣分，直接加进精确分和模型分。自动加入的水渠、堤坝在求解前按城市状况加进必建。提醒钉在方案定下后算：让 DMT 看不到旁边某片树林或雨林再算一次，少了加成就提醒。

伪代码 
function 单城求解(城市, 区域, 档位)
    表 = 单项表(区域, 城市的候选格)
    if 布局总数 ≤ 档位.穷举上限 then 最好 = 穷举(表)
    else
        束 = 集束搜索(按互惠从多到少排列的区域, 档位.束宽)
        最好 = 束里模型分最高的 档位.短名单 个布局中，DMT 精确分最高的
        对前 档位.起点数 个做 局部搜索；再做 档位.扰动轮数 轮 扰动重建
    end
    if 没有完整方案 then                   -- 少放 1 个、2 个……
        for 去掉 = 1, #必建 − 1 do
            对每种去掉法求解剩下的；if 找到 then break end
        end
    end
    return 最好, 质量(最好, 模型上界)
end

function 挑选求解(必建, 候选, 个数, 档位)
    组合表 = 从候选选 (个数 − #必建) 个的组合，去掉互斥的（分城的凑不够数时才保留），按乐观分排序
    for 组合 in 组合表前 档位.组合数 个 do
        if 乐观分(组合) ≤ 第三名的实际分 then break end
        粗解(必建 + 组合)
    end
    换类型(前三名)；前三名按本档位完整求解
    return 三套区域组合不同的方案
end

A.3多城联合规划（SDP_Multi）

几座城共用一张候选格表，重叠的格两城都能用但只能放一个对象；跨城的相邻加成照常计入。搜索沿用单城引擎，按城分块：一次只重解一座城，其他城固定。不同起点会走到不同的局部最优，所以跑一组固定的起点，取最好的。

参与的是全部城址钉，加上离任一新城 7 格内的现有城市（最多 8 座）。全帝国限量的区域（市政广场）只开剩余名额，放在清单里有它的各城候选格里。覆盖范围默认不计；打开后，工厂、动物园这类惠及周围城市的区域每多覆盖一座本方城市加权重分，半径从规则数据读。

A.4选城址（SDP_Sites + SDP_SiteSolver）

在上百个候选里挑 K 座：先用便宜的粗评筛，再只对一部分做带区域规划的精评，最后在精评过的城址里做组合搜索。

A.5分帧计算（SDP_Task）

游戏的界面 Lua 只有一个线程，一次算 6 秒，游戏就卡 6 秒。长计算放进协程，每帧算一份配额就让出，配额按上一帧的长短自动调整；两帧之间收起假想钉层，游戏其他部分看不到假想的区域。结果与在哪里切片无关。

工作单位：1 次 DMT 调用 = 1，1 次布局评估 = 0.25，20 个模型节点 = 1。游戏内一次算完每秒约 2 万单位，分帧时单城每秒 7400–9900、多城约 15000。

A.6住房与魅力（SDP_Appeal）

G1

社区按所在格的魅力给住房，保护区按自己的魅力给住房，并让周边未开发的地块按各自魅力多出产出。魅力又随方案变化，所以先算方案下每格的魅力，再查规则表。

这一项 = 住房权重 × 住房 + 各产出权重 × 周边产出，减去不规划时的值（城里已建、已打钉的社区降档也算进去）。周边产出只算必建的保护区：从候选里挑出的保护区只计住房，周边产出在结果里显示、标“候选，不计分”，否则后期几乎总是先挑保护区。区域占掉农场、牧场这类给住房的改良设施时城市少的住房（游戏把全城的“每块住房”加总后向下取整，农场每块 0.5），结果里单列一行提示，不计入分数：试过计入，面板默认设置下相邻加成和城市总产出都变差。建在树林上的区域，清掉的树林也不再计入本格；雨林、沼泽这类负值地貌清掉后本格不变。规则全部从规则表读：AppealHousingChanges、Adjacent_AppealYieldChanges、区域和地貌的魅力值；建区域清掉地貌要玩家有那项地貌的移除科技（树林要采矿），水面格魅力不变。游戏内校准：首都 4 格内 61 格魅力全部与预测相同；三张后期存档里，游戏按玩家的建造流程建出 9 个方案，社区、保护区格的魅力 17 格全部相同，改良设施住房 9 个全部相同，区域住房 9 个中 8 个相同（B.8）；保护区周边产出与规则表逐格相同。
