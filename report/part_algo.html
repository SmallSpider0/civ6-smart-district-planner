4.1增量 + 记忆评估（SDP_Board）

DMT 给一个区域打分时只看它自己的格子和周围 6 格。所以一个区域的分数完全由三样东西决定：区域类型、格子、6 个邻格上规划了什么。把邻格的规划编码成一个数（每个方向一位 64 进制数字），三者合起来做记忆键。移动一个区域时，只有它的旧位置、新位置及两处的邻格上的区域需要重新取分，其余的分数不变；取分时先查记忆，查不到才调用 DMT。

function 分数(区域, 格)
    码 = 邻居编码(格)                 -- 6 个方向各一位：邻格上规划的对象类型
    键 = (区域.类型, 格, 码)
    if 记忆[键] 存在 then return 记忆[键] end   -- 命中：不调用 DMT
    在假想钉层上摆好这一局面；清 DMT 的地块缓存
    记忆[键] = Σ 权重[产出] × DMT.GetBonusYields(区域)[产出]
    return 记忆[键]
end

function 放置(槽, 新格)                    -- Board:Put
    旧格 = 槽.格；槽.格 = 新格
    受影响 = {槽} ∪ 旧格 6 邻格上的对象 ∪ 新格 6 邻格上的对象
    for 对象 in 受影响 do
        总分 = 总分 − 当前分[对象] + 分数(对象, 对象.格)
    end
end
-- 合法性（CanPlacePin）同样按 (格, 区域) 记忆；奇观的合法性取决于邻格，按邻居编码记忆。

4.2单城搜索管线（SDP_Search）

先用一个便宜的线性模型在很宽的搜索面上找出一批好布局，再用 DMT 精确评估，最后用局部搜索和扰动重建修正模型的误差。模型只负责"往哪里找"，最终分数一律来自 DMT。

function 单城求解(城市, 区域列表, 档位)
    表 = 单项表(区域列表, 城市的候选格)      -- DMT 合法性、单项分、地块损失
    if 布局总数 ≤ 档位.穷举上限 then return 穷举(表) end
    顺序 = 按"与其他区域的互惠加成"从多到少排列区域
    束 = 集束搜索(顺序, 档位.束宽)          -- 用线性模型打分
    短名单 = 束里模型分最高的 档位.短名单 个布局
    最好 = 短名单里 Board 精确分最高的
    for 起点 in 短名单前 档位.起点数 个 do
        最好 = 较好者(最好, 局部搜索(起点))
    end
    repeat 档位.扰动轮数 次              -- 拆掉一片相邻的区域，按模型重放
        候选 = 局部搜索(扰动重建(最好))
        最好 = 较好者(最好, 候选)
    end
    return 最好, 质量(最好, 模型上界)
end

function 集束搜索(顺序, 宽)
    束 = { 空布局 }
    for 区域 in 顺序 do
        扩展 = 束中每个部分布局 × 该区域的每个空闲合法格
        束 = 扩展中模型分最高的 宽 个          -- 同分按格子序列字典序，结果确定
    end
    return 束
end

-- 线性模型（只用来排序，精确分一律来自 DMT）
模型分(布局) = Σ 单项分(区域, 格) − Σ 地块损失(格)
             + Σ 相邻两区域之间的互惠加成
             + 与已有区域、市中心的"不取整"加成   -- 凑满 N 个邻居才给一份的规则按比例计入

地块损失：k 个特色区域需要人口 P = max(人口, 3k − 2)，城市会耕作最好的 P 块地。一块地被区域占掉的损失 = 它的产出 − 第 P+1 好的地的产出（不小于 0），砍伐树林等一次性产出按 1/20 计。食物和地貌的权重只用于这一项。

同一张单项表还用在两处：单城页签的"好位置"对一个区域的每个合法格算它单独放下时的加权增益，从高到低分四档着色；单城页签选了奇观时，这座城按"只有一座城的多城问题"求解（见 4.3），沿用多城的奇观逻辑。

4.3多城联合规划（SDP_Multi）

参与城市是全部城址钉，加上离任一新城 7 格内的现有城市（最多 8 座）。每座城一组"槽位"，所有城的候选格合成一张表，重叠的格子两城都能用但只能放一个对象；有帝国上限的区域（政府广场）只开剩余名额。每座城可以有自己的区域清单；限量区域放在清单里有它的各城候选格的并集里，所以只写进一座城的清单就等于指定那座城。模板按产出从规则数据库推出（本文明有相邻规则产出该项的区域），不写死。搜索结束后，若有要求的对象没放上（例如学院四周被别的区域占满，大图书馆无处可放），再逐格试放它，并把它要挨着的区域和其他奇观重新安排；放上的对象更多的方案优先（G4）。补放有自己的计算预算，是本档位的四分之一。分块搜索沿用单城引擎：一次只重解一座城，其他城固定。因为不同起点会走到不同的局部最优，所以用一组固定的起点组合，并让重的档位先跑轻一档的起点。

多城页签可以另计覆盖范围，默认关。工厂、动物园等建筑惠及一定距离内的本方城市，同类不叠加；覆盖半径从规则数据读（工业区、娱乐中心 6 格，水上乐园 9 格）。权重为 w 时，每新覆盖一座城加 w 分。精确评估在 DMT 分和地块部分之外加上这一项；模型分里，每个区域按它单独放下时新覆盖的城数计入，所以模型仍偏乐观。原有的覆盖（已建、已打钉的同类区域）不重复计。

function 多城求解(城市, 每城区域, 奇观, 档位)
    if 档位.前置 then 用前置档位的参数跑完它的全部起点 end   -- 预算单独计算
    for s = 1, 档位.起点数 do
        顺序, 束宽 = 起点方案(s)    -- 1 逐城 2 联合 3 逐城窄束 4 逆序 5 逆序窄束 6+ 轮换
        布局 = 空
        for 城 in 顺序 do 布局 = 块求解(城的槽位, 布局) end   -- 前面的城固定
        布局 = 局部搜索(布局)                       -- 动作可以跨城
        repeat 档位.轮数 次
            for 城 in 顺序 do                        -- 其他城固定，重解这一座
                布局 = 较好者(布局, 块求解(城的槽位, 去掉该城后的布局))
            end
        end
        记录这个起点的结果
    end
    扰动重建(档位.扰动轮数)
    return 互不相同的前 3 套      -- 两套之间至少 max(2, 20% 槽位) 个对象位置不同
end
为什么要"前置"：参数不同的搜索（束宽、是否做交换动作、穷举上限）会落到不同的局部最优，轻档位偶尔能走到重档位走不到的形状。一个起点的结果只取决于输入和参数，所以标准档先跑快速档的起点，精细档先跑标准档的起点，重档位就不会低于轻档位的这些起点。共享的记忆评估让前置几乎不增加 DMT 调用。

4.4选城址（SDP_Sites + SDP_SiteSolver）

选城址要在上百个候选里挑 K 座，既要每座城本身好，又要彼此不抢地、资源不重复、能接力连回本方领土。先用便宜的粗评筛选，再只对一部分城址做包含区域规划的精评，最后在精评过的城址里做组合搜索。

function 选城址(K, D, 档位)
    候选 = 已揭示、可建城、与所有城市距离 > 最小城距、三环多半已揭示 的格
    for c in 候选 do 粗评[c] = 耕作 + 水源 + 奢侈 + 战略 + 地貌 + 魅力 − 风险 end
    按粗评从高到低排序
    while 已精评 < 档位.M do
        c = 粗评最高、尚未精评、且"能连回"的城址
            -- 距本方城市或城址钉 ≤ D，或距已精评的城址 ≤ D（最多 K−1 次接力）
        精评[c] = 粗评各项 + 在 c 用单城快速档规划区域得到的区域分 − 区域占掉的耕作分
    end
    分支定界(从精评城址中选 K 个):
        剪枝：已选的分 + 剩余最高的若干个分 ≤ 保留的第 Keep 名
        叶子：检查间距与接力连通
              组合分 = Σ 精评分 − 两城都能用的格归损失大的一方 − 重复的奢侈/战略种类
                       − 两城区域落在同一格时较小的一方
    return 互不相同的前 3 套     -- 每套至少有一个城址离更好的每套的所有城址 ≥ 2 格
end

4.5分帧计算（SDP_Task）

文明6的 UI Lua 只有一个线程，一次算 6 秒会让游戏卡住 6 秒。耗时的档位放进协程，每帧算一份"配额"后让出；配额按上一帧的长度自动调整。计算代码里每做一点工作就报一次工作量（Tick），配额用完就让出。结果与切片位置无关。

-- 每帧由 ContextPtr:SetUpdate 调用
function 每帧()
    配额 = 上一帧 > 1.25 × 目标 ? 配额 × 0.75 : (上一帧 < 0.75 × 目标 ? 配额 × 1.25 : 配额)
    安装假想钉层；coroutine.resume(计算)
    卸下假想钉层                         -- 帧与帧之间，游戏其他部分看不到假想钉
end
function Tick(单位)                       -- 计算代码里随处调用
    已用 = 已用 + 单位
    if 已用 ≥ 配额 then coroutine.yield() end
end
function 关闭面板()
    出队弹窗
    if 正在计算 then                       -- 隐藏的上下文收不到 SetUpdate
        只隐藏窗口控件，上下文保持显示；算完后再隐藏上下文
    end
end

工作单位：1 次 DMT 调用 = 1 单位，1 次布局评估 = 0.25 单位，20 个模型节点 = 1 单位。游戏内实测一次算完每秒约 2 万单位；分帧时单城每秒 7400–9900 单位、多城约 15000 单位（每帧约 30 毫秒，其余时间由游戏自己绘制）。
